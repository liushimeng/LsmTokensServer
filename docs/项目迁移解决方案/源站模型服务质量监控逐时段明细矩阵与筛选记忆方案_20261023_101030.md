## 一、背景与需求清单

阶段DB（v2.0.87）已完成「多窗口统计（近 1 天 / 1 周 / 1 月）+ 源站横向差异」改造，页面具备
统计窗口 / 趋势窗口 / 趋势指标三组筛选按钮与全模型同屏展示能力。本阶段聚焦**逐时段明细模块**
的可读性与其筛选状态的可记忆性，核心增量是：

1. **逐时段明细矩阵去竖向滚动**：表格随页面纵向撑开，不再锁在 460px 高的框内。
2. **四维同显**：请求数 / 拥堵系数 / 错误率 / 成功平均时延合并到同一张分组列矩阵，
   删除互斥的指标切换按钮。
3. **全模型逐时段明细表默认折叠**：14 项指标的长表默认隐藏，可展开，展开状态记忆。
4. **三组筛选按钮全量排查**：未实现的补实现、显示缺陷一并修复，并全部接入 localStorage 记忆。
5. 同步更新 `./docs/*/*.md` 知识库。

## 二、现状分析

### 2.1 逐时段明细模块结构（`index.jsx` ⑦）

```
⑦ 逐时段明细（时段 × 模型 矩阵 + 全模型长表）
   ├─ QoSPeriodMatrix   指标切换按钮(4) + 时段×模型 单值热力矩阵（maxHeight 460，竖向滚动）
   └─ QoSPeriodTable    DataTable 长表（模型 × 时段，14 项指标）—— 恒展开，行数 = 模型数 × 时段数
```

问题：

- **P1 竖向滚动**：`QoSPeriodMatrix` 外层 `maxHeight:460 / overflowY:'auto'`，60 个分钟桶（近 1 小时窗口）时表头被"钉"在 460px 的框里，视线要在 460px 高的窗口内反复上下扫，且与页面其余模块割裂。
- **P2 一次只能看一个维度**：4 个指标按钮互斥，运维要比较"同一时段某模型的拥堵系数 vs 错误率 vs 时延"必须反复点按钮 + 反复扫表。
- **P3 长表常驻**：模型数 × 时段数的 14 列表格默认全展开，把页面尾部（热力图 / 错误分布 / 全模型明细表）挤到很下面，且 14 列横向滚动成本高。

### 2.2 筛选按钮链路（`index.jsx` 顶部置顶筛选行）

| 按钮组 | 取值 | 作用范围 | 现状 |
|---|---|---|---|
| 统计窗口 | 近 1 天 / 近 1 周 / 近 1 个月 | 状态总览 / 时段画像 / 时段带矩阵 / 质量对比 | 已实现 |
| 趋势窗口 | 近 1 小时 / 近 24 小时 / 近 7 天 / 近 30 天 | 趋势图 / 逐时段明细 / 错误分布 | 已实现 |
| 趋势指标 | 平均时延 / P95 / 拥堵系数 / 卡顿率 / 错误率 | 趋势图 | 已实现 |

**但存在 4 个真实缺陷（见 §四 D1~D4）**，且**三个筛选组的状态完全不做持久化**，刷新即回落默认
（`statWin='7d'` / `win='24h'` / `metricKey='avg'`）。

## 三、设计总览

```
⑦ 逐时段明细（{趋势窗口}）
   ├─ ⑦-1 时段 × 模型 四维明细矩阵      ← 重构（需求 1、2）
   │      双层表头：模型分组 → 4 子列（请求数 / 拥堵系数 / 错误率 / 成功平均时延）
   │      行 = 时段（近 1h 60 行 / 24h 24 行 / 7d 7 行 / 30d 30 行），无竖向滚动
   │      首列「时段」粘性；拥堵系数格按四档状态色；错误率超阈值文字标红；末行「合计」
   └─ ⑦-2 全模型逐时段明细表（14 项指标）  ← 折叠/展开（需求 3）
          默认折叠隐藏；展开按钮 + 行数提示；localStorage 记忆
```

顶部置顶筛选行（三组按钮）全部接入 localStorage 记忆（需求 4）。

## 四、详细设计

### 4.1 `QoSPeriodMatrix.jsx` 重构（需求 1、2）

**输入**：`{ models, allNames, win, t }`（不变）

**删除**：

- 指标切换按钮组（`PERIOD_MATRIX_METRICS.map` + `metricKey` state）
- 外层 `maxHeight: 460 / overflowY: 'auto'`

**新增结构**：

| 层 | 内容 |
|---|---|
| 表头行 1 | `时段`（rowspan=2，粘性左列）+ 每个模型一个 `<th colspan=4>`（模型名 + 色点 + 标题 tooltip） |
| 表头行 2 | 每个模型下 4 个子列：请求数 / 拥堵系数 / 错误率 / 成功平均时延 |
| 表体行 | 时段（升序，与桶序一致）+ 每个模型 4 格 |
| 合计行 | **按模型分组**给出该模型在全部时段上的汇总：请求数合计 / 拥堵系数（按系数样本加权）/ 错误率（按请求数加权）/ 平均时延（按成功数加权）；全站口径见页面顶部 KPI 卡 |

**单元格取值口径**（与后端一致，零口径漂移）：

| 维度 | 字段 | 格式 | 着色 |
|---|---|---|---|
| 请求数 | `count` | 千分位 | 无（量级） |
| 拥堵系数 | `avg_congestion` | 两位小数 | 四档状态色背景（低样本 `coefficient_samples < 5` → `—` 灰底） |
| 错误率 | `error_rate` | 百分比 | 仅文字色（> 5% 严重色），不做背景色（避免与拥堵系数双色阶混淆） |
| 成功平均时延 | `ok_avg_elapsed_ms` | `fmtMs` | 无（量级） |

**合计行计算**：

- 请求数 = `Σ count`
- 拥堵系数 = `Σ(avg_congestion × coefficient_samples) / Σ coefficient_samples`（低样本格不参与）
- 错误率 = `Σ(error_rate/100 × count) / Σ count × 100`
- 平均时延 = `Σ(ok_avg_elapsed_ms × success_count) / Σ success_count`

**布局细节**：

- 外层 `overflowX: 'auto'`（不设 max-height → 无竖向滚动条，表格随页面撑满）
- 首列 `position: sticky; left: 0; background: #fff; zIndex: 2`（横向滚动时时段列不丢）
- 模型分组头 `minWidth: 230 / maxWidth: 320`，模型名 `maxWidth: 180` 省略号 + title；子列不换行
- 保留共享图例（四档状态色 + 无数据/低样本）+ 口径脚注

### 4.2 `QoSPeriodTable.jsx` + `index.jsx` 折叠（需求 3）

- `index.jsx` 新增 state `periodTableOpen`（默认 `false`），持久化 key `lsm:serviceQuality:periodTableOpen:{manager|user}`。
- 折叠态：只渲染标题行 + 「展开明细表」按钮 + 折叠提示（`共 N 行 · 14 项指标`）。
- 展开态：渲染 `QoSPeriodTable`（14 指标不变）+ 「收起明细表」按钮。
- 行数由 `index.jsx` 按同一 `windowSeries` 口径**预计算**（避免组件内重复计算与行数回传造成的额外渲染）。

### 4.3 筛选状态持久化（需求 4）

新增 `ClientWeb/src/pages/service-quality/prefs.js`（纯函数，node 可直跑自检）：

```js
qosPrefKey(role, name)       // lsm:serviceQuality:{name}:{manager|user}
loadQosPref(key, allowed, fallback)  // 读 localStorage + 白名单校验 + 异常兜底
saveQosPref(key, value)
```

`index.jsx` 三个 state 改为「记忆初始化 + 变更写盘」：

| state | key | 白名单 | 默认 |
|---|---|---|---|
| `statWin` | `statWin` | `24h/7d/30d` | `7d` |
| `win` | `trendWin` | `1h/24h/7d/30d` | `24h` |
| `metricKey` | `trendMetric` | `avg/p95/congestion/stall/error` | `avg` |

角色由构建期常量决定：`index.jsx` 取 `currentRole()`（即 `shared/auth` 的 `BUILD_ROLE = __APP_ROLE__`，
管理员端恒为 `manager`、用户端恒为 `user`，与双构建隔离规范一致），再作为参数传入 `qosPrefKey(role, name)`。
`prefs.js` 本身**不引用** `__APP_ROLE__` 全局（node 直跑自检时该全局不存在），
管理员端 / 用户端记忆互不污染。

### 4.4 `index.jsx` 其余联动修正（需求 4）

1. **KPI 告警卡提示**：`alertsHint` 原文写死「近 24h」，改为跟随统计窗口的新键 `alertsHintWindow`。
2. **⑩ 全模型服务质量明细表**：状态 / 拥堵系数 / 平均时延 / P95 / 峰 / 谷 六列由硬编码 `stats_24h` / `week_ok_p95_ms` / `peak_valley` 改为跟随统计窗口 `windowStats(m, statWin)` / `windowPeakValley(m, statWin)`，列标题带窗口名（`table.titleWindow` / `table.coeffWindow` / `table.avgWindow` / `table.p95Window`）；原独立的「30 天拥堵系数」列被窗口化列覆盖后删除（避免同语义两列并存）。
3. **DataTable 排序键隔离**：本页有 2 张 DataTable，DataTable 默认排序持久化 key 只按「角色 + 路径」生成 → 两表共享（`model` 等同名列会串味）。为两张表分别显式传 `sortStorageKey`（`lsm:serviceQuality:sort:periodTable:{role}` / `lsm:serviceQuality:sort:modelTable:{role}`）。
4. **逐时段明细标题**带当前趋势窗口，避免"看的是哪段数据"歧义。

### 4.5 缺陷修复（需求 4 排查结论）

| # | 位置 | 缺陷 | 修复 |
|---|---|---|---|
| D1 | `QoSTrendChart.jsx` | `bucketCount` 取 `series[0]`（第一个模型）的桶数，若某模型桶数更多则后段点被裁出坐标轴 | 改为取所有系列桶数最大值 |

| D3 | `index.jsx` ⑩ 表 | 状态 / 系数 / 时延列写死 24h，与顶部「统计窗口」按钮脱节（按钮"点了没反应"的观感来源） | 改为跟随统计窗口 |
| D4 | `index.jsx` | KPI 告警提示写死「近 24h」 | 跟随统计窗口 |

## 九、风险与回滚

| 风险 | 缓解 | 回滚 |
|---|---|---|
| 分组列矩阵列数 = 模型数 × 4，模型多时横向很长 | 外层横向滚动 + 首列粘性 + 模型名省略号；合计行给出全量口径 | 回退 `QoSPeriodMatrix.jsx` |
| localStorage 记忆值非法（手工改写 / 旧版本遗留） | 白名单校验，非法值回落默认值 | 无需回滚 |
| 用户端与管理端共用页面但记忆互相污染 | key 带角色后缀（`manager` / `user`） | 无需回滚 |
| 明细表默认折叠后用户"找不到数据" | 折叠态保留标题行 + 展开按钮 + 行数提示与口径说明 | 回退 `index.jsx` |
| 两张 DataTable 排序键未隔离导致串味 | 显式传 `sortStorageKey` 区分 `periodTable` / `modelTable` | 回退 `index.jsx` |
| rebuild 中断在线服务 | 遵守 `AGENTS.md`：验证期间不并发 rebuild；仅本阶段末调用一次 | — |
