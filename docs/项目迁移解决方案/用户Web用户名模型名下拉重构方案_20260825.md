# 用户 Web 服务 用户名/模型名功能重构方案（阶段Y）

> 日期：2026-08-25。承接阶段X（管理端用户名/模型名下拉联动），
> 本阶段将同样的体验落到**用户端构建（dist-user，端口 29001）**。

## 1. 需求

1. 用户端已有登录鉴权（JWT claims 携带 `user_id`/`user_name`），页面**不需要**任何用户名选择/输入控件。
2. 所有用户端页面中「模型名」相关控件统一为 **下拉列表**，数据来自本人模型列表。
3. 下拉数据在**页面生命周期内只请求一次**（模块级缓存，SPA 路由切换共享），浏览器刷新自动重取；避免点一下查一次接口/数据库。
4. 后端已确认：用户端全部业务 handler（`userChatAnalysis*`、`userChatDialogInterfaceHandle`、`userModelListInterfaceHandle` 等）**强制以 claims.UserID/UserName 覆盖请求参数**，前端传的 `user_name` 一律被忽略，无需新增后端接口。

## 2. 现状问题

| 页面 | 问题 |
|---|---|
| ChatDialog | 用户端仍是**手输用户名** `<input placeholder="user_name">` + 手点「加载模型列表」按钮 |
| ChatAnalysis / Session / Task / Total | 用户端模型下拉数据靠各页各自 `fetchMyModels()`（UserModelListInterface）请求，**每进一次页面就查一次库**，5 处重复样板 |

## 3. 方案

### 3.1 前端 shared/userModelOptions.js 增加用户端分支

- 新增模块级缓存 `myModelsCache` 与 `loadMyModelNames()`：`__APP_ROLE__ === 'user'` 时 `post('UserModelListInterface', {})`，仅取 `model_name` 数组，失败清缓存可重试；`manager` 构建下直接返回空数组（接口名经 Rollup DCE 裁剪，不进 dist-manager）。
- 新增 `useMyModelNames()` Hook：挂载加载一次，返回 `{modelNames, loading}`；SPA 内路由切换共享缓存，**全站用户端仅请求一次**；浏览器刷新重建模块即自动重取。
- 新增 `clearMyModelOptionsCache()` 手动失效入口（登出/后续自助管理场景）。
- 管理端原有 `useUserModelOptions` 能力保持不变，双端语义统一：管理端=全站用户级联，用户端=本人模型。

### 3.2 四个分析页去样板

ChatAnalysis / ChatAnalysisSession / ChatAnalysisTask / ChatAnalysisTotal：
- 删除各自的 `myModels` state + `fetchMyModels()` effect 样板，统一改用 `useMyModelNames()`；
- `modelOptions` 用户端分支改为 `myModelNames`；
- 「进入页面自动选第一个模型并查询」逻辑改为监听 `myModelNames` 到达后触发（依赖缓存，不再重复请求）；
- 提交参数 `user_name` 用户端直接省略（后端强制 claims，传了也被忽略）。

### 3.3 ChatDialog 用户端改造

- **移除用户端用户名手输框与「加载模型列表」按钮**：登录态即身份，进入页面自动拉取本人模型列表（后端 `action:'models'` 已按 claims.UserID 查询，请求不再携带 `user_name`）；
- 管理端交互（用户名级联下拉 + 手动加载）保持不变。

### 3.4 后端

零新增接口。护栏测试补充：用户端路由 mux 上**不注册** `UserModelOptionsInterface`（该接口返回全站用户名列表，绝不能暴露到 29001）。

## 4. 验证

- `go vet ./...` + `go test ./...` 全绿；
- `./rebuild_restart_app.sh` 双构建 + 重启，`dist-user` grep 复验不含 `UserModelOptionsInterface` 管理端字样；
- 29001 实测：ChatDialog 页无用户名输入框、模型自动加载；各分析页模型下拉一次加载、路由切换不重复请求。
