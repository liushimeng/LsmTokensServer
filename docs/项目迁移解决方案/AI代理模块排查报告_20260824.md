## 3. 发现并修复的 bug

### 🔴 Bug-1（关键）：AI 代理 HTTPS 端口（29003）静默跳过未启动

**症状**：`https://localhost:29003/OpenAI/v1/models` 返回 `HTTP 000`（无响应），端口未监听。

**根因**：`StartAIProxyService` 的证书路径通过 `config.ResolvePath` 解析，基准目录是 `os.Executable()` 返回的可执行文件所在目录（`ServerGo/`）。
旧工程证书路径 `server.crt` 通过相对当前工作目录解析（`./server.crt` 在工程根目录），所以能找到。
新工程证书在工程根目录，解析后变成 `ServerGo/server.crt`（不存在），于是代码静默 `return` 跳过 HTTPS 启动。

**日志证据**：
```
[PROXY] HTTPS proxy cert file not found (/usr/local/LsmTokensServer/LsmTokensServer/ServerGo/server.crt),
skip HTTPS proxy on :19003
```

**影响**：29003 HTTPS 代理在迁移后无法对外服务，外部必须降级到 29000 HTTP。属于阻塞性 bug。

**修复**（`proxy/server_http_ai_proxy.go`）：在证书查找失败时回退到 `os.Args[0]` 父目录（即工程根目录）。
```go
if _, err := os.Stat(certFile); err != nil {
    parentCert := filepath.Join(filepath.Dir(os.Args[0]), "..", config.G.UserWebCertFile)
    if _, err2 := os.Stat(parentCert); err2 == nil {
        certFile = parentCert
    } else {
        // 仍找不到才静默跳过
    }
}
```

**修复后验证**：`https://localhost:19003/OpenAI/v1/models` 返回 401（鉴权），与旧服务一致；端口真正 LISTEN。

### 🟡 Bug-2（次要）：用户 Web HTTPS（29001）相同路径问题

**症状**：与 Bug-1 同源，但 `webserver.StartUserWebServer` 也走 `config.ResolvePath` 解析证书，存在同样的工程根目录证书丢失问题。

**修复**（`webserver/webserver.go`）：在 `StartUserWebServer` 的证书查找中，先尝试可执行文件目录，失败后回退到父目录（工程根）。
