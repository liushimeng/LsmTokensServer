# 阶段7：路由调度与缓存机制深度优化方案

> 日期：2026-08-26
> 范围：代理转发调度算法、内存缓存机制、MySQL 统计查询、智能路由细节
> 旧程序参考：`/usr/local/LsmHttpAgent/`
> 新程序目标：`/usr/local/LsmTokensServer/LsmTokensServer/ServerGo/`

---

## 一、背景与目标

### 1.1 背景

LsmTokensServer 已完成主体架构迁移（阶段1~6），前端国际化（阶段U），双构建隔离（阶段T）。但在代理转发调度算法、内存数据库/缓存机制、智能路由细节方面，经与旧程序 `/usr/local/LsmHttpAgent/` 全面对比，发现以下可优化空间：

1. **缓存可观测性不足**：StatsCache 缺少命中率统计，无法评估缓存效能
2. **路由决策指标缺失**：经济型/稳定型算法的选择、失败、冷却事件未被量化采集
3. **健康检查粒度过粗**：上游连通性测试缺少定期自动探测与指标上报
4. **统计查询存在优化空间**：部分全表扫描场景可进一步利用覆盖索引
5. **WebSocket 流式聚合可增强**：7 维度累加器缺少错误率/成本维度

### 1.2 目标

| 维度 | 目标 | 验收标准 |
|------|------|----------|
| 缓存可观测性 | 添加 StatsCache 命中率、大小、淘汰数统计 | `/ChatAnalysisTotal` 接口返回 cacheStats |
| 路由指标 | 采集算法选择/失败/冷却事件计数 | 内存原子计数，WS 推送可选携带 |
| 健康检查 | 定期探测上游端点并记录成功率 | 后台 goroutine，可配置间隔 |
| 查询优化 | 全站聚合走覆盖索引 | EXPLAIN 无 Using filesort |
| WS 聚合增强 | 新增错误率/成本维度 | streamChatStats 推送 9 维度 |

## 三、差距分析（需补全的功能）

### 3.1 差距项清单

| 编号 | 差距项 | 优先级 | 影响范围 | 预估工时 |
|------|--------|--------|----------|----------|
| G1 | StatsCache 命中率/大小/淘汰统计 | P0 | 缓存可观测性 | 0.5d |
| G2 | 路由决策指标采集（选择/失败/冷却） | P1 | 运维可观测性 | 1d |
| G3 | 上游定期健康检查与指标上报 | P1 | 可靠性 | 1d |
| G4 | 全站聚合覆盖索引优化 | P1 | 查询性能 | 0.5d |
| G5 | WS 流式聚合新增错误率/成本维度 | P2 | 数据完整性 | 1d |
| G6 | 经济型算法冷却事件回调钩子 | P2 | 可扩展性 | 0.5d |

### 3.2 详细差距描述

#### G1：StatsCache 可观测性

**现状**：`StatsCache` 仅维护 `entries map[string]*StatsCacheEntry`，无命中/未命中/淘汰计数。

**目标**：
- 添加 `hits/misses/evictions` 原子计数器
- 提供 `GetStatsCacheMetrics()` 返回命中率、当前大小、TTL
- WS 推送可选携带 cacheStats

**文件**：`ServerGo/models/mysql_http_stats_cache.go`

#### G2：路由决策指标采集

**现状**：经济型/稳定型算法的选择、失败、冷却事件未被量化。

**目标**：
- 添加 `RoutingMetrics` 结构：`selections/failures/cooldowns/rotations` 原子计数
- 按算法类型分桶统计
- 提供 `GetRoutingMetrics()` 接口

**文件**：`ServerGo/models/agent_algorithm.go`（新增 metrics 字段）

#### G3：上游定期健康检查

**现状**：`TestDstEndPointConnectivity()` 仅在添加/更新源站时手动触发。

**目标**：
- 后台 goroutine 定期探测所有启用源站
- 记录最近 N 次探测结果（成功率、延迟）
- 提供 HTTP 端点查询上游健康状态

**文件**：`ServerGo/system/ai_api_connectivity.go`（扩展）

#### G4：覆盖索引优化

**现状**：部分全站聚合查询仍回表。

**目标**：
- 为高频统计查询添加覆盖索引
- 确保 EXPLAIN 使用 index only scan

**文件**：`ServerGo/models/subtable.go`（索引调整）

#### G5：WS 流式聚合新增维度

**现状**：`chatStatsAggregator` 有 7 维度（kpi/time/tokens/model/trend/protocol/agent）。

**目标**：
- 新增 `error_stats`（按状态码分桶）
- 新增 `cost_stats`（按模型成本聚合）

**文件**：`ServerGo/websocket/server_ws_chat_total_stream.go`

#### G6：经济型冷却事件回调

**现状**：`CooldownEndpoint()` 仅修改内存状态，无外部通知。

**目标**：
- 添加 `OnEndpointCooldown` 回调钩子
- 可选触发日志记录或事件通知

**文件**：`ServerGo/models/agent_algorithm_economic.go`

## 五、风险与注意事项

### 5.1 性能风险

| 风险 | 缓解措施 |
|------|----------|
| 原子计数影响热点路径 | 使用 `atomic.Int64`，无锁；仅在算法入口/出口计数 |
| 健康检查占用连接 | 独立 http.Client，超时 10s，不占用代理连接池 |
| 覆盖索引增加写入开销 | 仅添加 1~2 个高频查询所需索引 |

### 5.2 兼容性风险

| 风险 | 缓解措施 |
|------|----------|
| WS 协议新增字段 | 添加在消息结构末尾，旧客户端忽略 |
| 新增配置项 | 提供默认值，不破坏现有配置 |

### 5.3 安全红线

- 健康检查端点仅返回聚合指标，不暴露 API Key
- 路由指标仅内存计数，不落库敏感信息
- 所有新增接口遵循 ManagerAuthMiddleware 保护
