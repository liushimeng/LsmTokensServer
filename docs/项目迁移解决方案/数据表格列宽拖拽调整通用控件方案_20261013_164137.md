# 数据表格列宽拖拽调整通用控件方案

> 版本：v1.0　日期：2026-10-13　阶段：CU（v2.0.80）
> 范围：`ClientWeb/` 管理员 Web（9101）与用户 Web（29001）全部数据表格

## 1. 需求分析

1. 所有数据表格的**表头行**支持**拖拽调整列宽**（如 `/ChatAnalysis` 对话记录数据表的 ID/时间/方法/URL/状态/目标模型/转发类型/输入 Tokens/输出 Tokens/耗时/Agent工具/Agent工具定义/AgentSessionID/操作 等列）。
2. 每张数据表的列宽持久化到 **localStorage**，刷新后恢复。
3. 列宽以**占整个数据表宽度的百分比**等比例计算（容器变宽变窄时各列等比例缩放）。
4. 遍历管理员/用户 Web 全部子页面、全部数据表格，抽象出**通用性控件**统一处理。
5. 各数据表设计各不相同，但共用同一**基类控件**——恰好对应现有架构：全站表格均已收敛到共享基类组件 `src/components/DataTable.jsx`。

## 3. 总体设计

### 3.1 架构：一个基类控件 + 纯函数工具模块

```
src/shared/columnResize.js        # 纯函数（可 node 直测）：key 生成、百分比换算、拖拽增量钳制
src/components/DataTable.jsx      # 基类控件：集成 colgroup + 表头拖拽把手（全站唯一改动点）
src/index.css                     # 拖拽把手样式 + fixed 布局类
ToolbarDialogs.jsx                # 2 处手写表格改用 DataTable（统一纳入通用控件）
```

### 3.2 存储设计

- key：`lsm:datatable:colwidth:{role}:{path}:{colsHash}`
  - `role`：`__APP_ROLE__`（manager/user），与排序持久化一致；
  - `path`：`window.location.pathname`；
  - `colsHash`：列 key 序列（含是否含折叠开关列）的 djb2 哈希 → base36。**同页多表（ChatAnalysisTotal 11 张、Task 2 张）靠列 keys 天然区分**，同一张表列定义稳定故哈希稳定。
- value：`{ v: 1, widths: { colKey: pct }, ts: 更新毫秒 }`
  - `pct` 为**数据列可用宽度**的百分比（折叠开关列占 40px 固定宽度，从总宽扣除后再等比分配）；
  - 载入时校验：版本、key 集合与当前列完全一致，否则丢弃（防止列结构变更后错位）。
- 百分比满足需求 3：容器缩放时各列等比例缩放（`table-layout: fixed` + `<col style="width:X%">`）。

### 3.3 交互设计

| 交互 | 行为 |
|---|---|
| 悬停表头列右缘 | 显示 `col-resize` 光标与把手高亮条 |
| 拖拽把手 | 被拖列与其余列此消彼长，实时像素级预览；`user-select: none` 防误选；最小列宽 48px。**让出顺序**：右邻列优先 → 不足则按序溢出到更右侧列 → 最后动用左侧列（把宽表里"紧邻列已接近最小宽导致拖不动"的死角消除，总宽恒不变） |
| 松开 | 当前各列像素宽 → 百分比归一（Σ=100）→ 写 localStorage → 切换为 `table-layout: fixed` 百分比布局 |
| 双击把手 | 清除该表存储并恢复自然布局（重置列宽） |
| 已存储列宽的表 | 挂载时直接按百分比渲染（fixed 布局），刷新不跳变 |

- 拖拽期间从 `th` 实测像素宽作为基准：未存储过列宽的表在首次拖拽瞬间采集当前自然布局宽度，**拖拽前视觉零变化、零回归**。
- 排序点击与拖拽把手互斥：把手 `pointerdown` 阻止冒泡，不会触发三态排序。
- 把手 `title` 走 i18n（zh/en/ja）：`datatable.colResize` = "拖拽调整列宽，双击重置"。

### 3.4 DataTable 新 props（默认值保持全站零改动自动生效）

- `enableColumnResize`（默认 `true`）：总开关；
- `resizeStorageKey`：显式指定 key；传 `null` 且 `enableColumnResize` 时可禁用（与 enableSortPersist 模式一致）。

### 3.5 手写表格改造

ToolbarDialogs.jsx 中 2 处原生 `<table>` 改为 DataTable：
- Git 提交记录表：`collapsible + expandedIds + renderExpandedRow`（替代原手写展开行，交互与对话分析详情一致，行首出现 ▶/▼ 开关列）；
- CPU Top 进程表：三列直接 columns 化。
两表自动获得列宽拖拽能力，达成"每一个数据表都走通用性控件"。

### 3.6 为何不需要 SubAgent 分发到各页面

需求 4/5/6 预想"逐页逐表改造"，但盘点结论是全站表格已 100% 收敛到 DataTable 基类组件，能力在基类实现一次即全站生效；逐页派发 SubAgent 反而引入不一致风险。按 AGENTS.md"并行优先"原则的意图（缩短工时），中心化改动的工时更短、回归面更小，故采用**基类单点实现**，SubAgent 非必要。

## 5. 风险与对策

| 风险 | 对策 |
|---|---|
| 首次拖拽切换 fixed 布局引起列宽跳变 | 拖拽瞬间以 th 实测像素宽为基准，跳变 ≤1px |
| localStorage 存留旧列结构数据 | 载入校验 key 集合完全一致，否则丢弃 |
| 卡片模式（手机端）布局破坏 | card-mode 下 thead 隐藏、colgroup 失效，天然免疫 |
| 同页多表 key 冲突 | colsHash 区分 |
| 折叠开关列（40px）与百分比混用溢出 | 数据列百分比以"总宽-40px"为基准归一 |
| 排序点击被把手误触发 | 把手 pointerdown stopPropagation + preventDefault |
| user 构建产物膨胀 | 纯前端组件逻辑，无管理端接口/页面引用，双构建隔离不受影响 |
