# 管理员与用户 Web 服务双构建隔离升级方案（20260825）

> 阶段 T：管理员 Web 服务（`managerWebListenPort`，规范 9101）与用户 Web 服务（`userWebListenPort`，规范 29001）的**前端构建产物完全隔离**。
> 前置阶段：S（ChatAnalysisTotal 区间报告）、Q（全面安全加固）、R（402 故障转移）。

## 1. 背景与现状

升级前（v2.0.46~S 阶段末）架构：

| 隔离层 | 现状 | 结论 |
|---|---|---|
| 网络层 | 两个独立 mux / HTTP server / 端口，用户端支持 HTTPS + 严格限流 + 防重放 | ✅ 已隔离 |
| API 层 | 同名路由挂不同 handler，用户端按 JWT claims 过滤数据；管理端 `ManagerAuthMiddleware`、用户端 `userAuthMiddleware` | ✅ 已隔离 |
| **静态资源层** | **两端共用同一 `ClientWeb/dist` 产物，同一 JS bundle**；管理端页面代码（UserManage、ManagerLogin 等）在用户端口也可下载 | ❌ 未隔离 |

缺口：用户端 29001 端口下发的 JS bundle 内含全部管理端页面代码与接口调用字符串，仅靠运行时 401/302 拦截。一旦某用户端 handler 漏加鉴权，攻击者已掌握全部管理端接口路径与参数契约，攻击面显著放大。

## 2. 升级目标

1. **一套源码，两套产物**：`ClientWeb` 源码复用，构建输出 `dist-manager/` 与 `dist-user/` 两套完全独立的 bundle。
2. **用户端产物零管理代码**：`dist-user` 中不得包含 `UserManage`、`ManagerLogin` 页面代码及其专属接口调用（`UserManageInterface`、`ManagerLoginInterface` 等）。
3. **服务端静态目录绑定角色**：管理端 mux 只托管 `dist-manager`，用户端 mux 只托管 `dist-user`，不存在共享目录或跨目录回落。
4. 角色由**构建期常量**决定（而非端口嗅探/运行时探测），`__APP_ROLE__` 经 Vite `define` 静态替换，配合动态 `import()` 实现管理页代码在用户端构建中被 Rollup 死代码消除（chunk 不产出）。
5. 构建脚本 `./rebuild_restart_app.sh` 一次产出双份产物。

## 3. 前端设计（ClientWeb）

### 3.1 vite 双模式构建

- `vite.config.js` 导出 `({ mode }) => config` 函数：
  - `mode === 'manager'` → `outDir: 'dist-manager'`，`define: { __APP_ROLE__: '"manager"' }`
  - `mode === 'user'` → `outDir: 'dist-user'`，`define: { __APP_ROLE__: '"user"' }`
  - dev（`vite`，mode=development）默认 manager（功能全量，便于本地调试）。
- `package.json`：
  - `"build": "npm run build:manager && npm run build:user"`
  - `"build:manager": "vite build --mode manager"` / `"build:user": "vite build --mode user"`

### 3.2 页面注册表懒加载 + 构建期裁剪

`src/App.jsx`：

- `PAGES` 由静态 import 组件改为 `() => import('./pages/Xxx')` 懒加载器，渲染用 `React.lazy` + `<Suspense>`。
- 管理员专属页（`ManagerLogin`、`UserManage`）仅在 `__APP_ROLE__ === 'manager'` 分支注册。`define` 将条件替换为常量比较（如 `'user' === 'manager'`），Rollup 死代码消除连同内部 `import()` 一并移除 → 用户端产物**不产出**对应 chunk。
- 双端共用页（AIRouteManage、DstEndPointManage、AgentInfo、ProtocolConvertAnalyzer、SpiderDataSource 等）保持共用，页面内部已有的 `isAdmin` 分支继续生效。

### 3.3 角色来源改造（auth.js / api.js / App.jsx）

- `auth.js` 新增 `export const BUILD_ROLE = __APP_ROLE__`；`currentRole()` 优先返回 `BUILD_ROLE`（构建期常量，权威来源），localStorage `lsm.role` 兜底仅用于兼容。
- `api.js` 401 分流：manager 构建 → `/ManagerLogin`；user 构建 → `#/Login`（不再嗅探端口/localStorage）。
- `App.jsx` 删除运行时角色探测（POST `UserManageInterface` 探测逻辑）：user 构建下**根本不发起**该请求（顺带消除一处用户端无谓的管理接口探测流量）；manager 构建下角色恒为 manager，`UserInfoInterface` 失败即跳 `/ManagerLogin`。
- `Layout` 的 `isAdmin` 由 `BUILD_ROLE === 'manager'` 合成；菜单 `NAV_TREES.admin/user` 保持两套配置按角色选用（user 树本就不含 `UserManage`）。

### 3.4 页面归属分类（复用矩阵）

| 页面 | manager 构建 | user 构建 | 说明 |
|---|---|---|---|
| ManagerLogin / UserManage | ✅ | ❌（chunk 不产出） | 管理员专属 |
| Login | ❌ | ✅ | 用户登录（用户名+密码 / 模型名+API Key 两种，均带用户维度 JWT 权限） |
| Home / ChatAnalysis* / ChatDialog / SpiderDailyInfo / CleanupReport | ✅ | ✅ | 查询分析类，用户端按 claims 过滤数据 |
| AIRouteManage / ModelInfo / AgentInfo / ProtocolConvertAnalyzer / DstEndPointManage / SpiderDataSource | ✅ | ✅ | 双端共用，页面内 `isAdmin` 分支：管理端全量增删改，用户端只读/本人数据受限编辑 |

## 4. 后端设计（ServerGo）

### 4.1 webserver 静态目录按角色（webserver.go）

- `clientWebDist(role string)`：候选 `execDir/../ClientWeb/dist-{role}` 与 `execDir/ClientWeb/dist-{role}`。
- `mountSPA(mux, role)`；`buildManagerMux` → `dist-manager`，`buildUserMux` → `dist-user`。
- **不回落共享目录**：角色目录缺失时仅日志告警（API-only），杜绝两端互取对方产物。

### 4.2 config 可选覆盖

`config.LsmTokensServerConfig` 新增可选字段 `managerWebStaticDir` / `userWebStaticDir`（默认空 → 使用角色默认目录）；便于异机部署时指向独立挂载的静态目录。`.conf.example` 同步补充说明。

### 4.3 API 层不变

管理端 / 用户端路由注册、鉴权中间件、bcrypt/JWT（阶段 Q 成果）全部复用，不在本阶段调整。

## 5. 构建脚本（rebuild_restart_app.sh）

前端构建步骤改为 `npm run build`（内部产出 `dist-manager` + `dist-user`），部署/日志输出同步改为双目录。

## 6. 验证清单

1. `npm run build` 后：`dist-user/` 中 grep 无 `ManagerLogin`、`UserManage`、`ManagerLoginInterface`、`UserManageInterface` 字样；`dist-manager/` 功能完整。
2. `go build ./...`、`go vet ./...`、`go test ./...` 全绿（新增 webserver 角色目录定位单测）。
3. 完整重启后：
   - 9101/29101（管理端）→ 返回 `dist-manager/index.html`，未登录访问业务接口 401/302 `/ManagerLogin`。
   - 29001（用户端，HTTPS）→ 返回 `dist-user/index.html`，管理接口 404（mux 未注册）。
   - 用户端用户名登录与模型名登录均正常，数据按用户/模型维度过滤。

## 7. 规则沉淀

- `CLAUDE.md` §2 新增：**Web 前端必须双构建（dist-manager/dist-user），管理端与用户端静态产物严禁共享；管理员专属页面/接口调用不得进入用户端产物。**
- `docs/开发指南/AGENT.md`、`AGENT_INDEX.md`、`docs/INDEX.md` 同步索引本方案。

## 8. 风险与回滚

- 风险：脚本未跑双构建导致某端口 404/空白 → 脚本内单命令原子产出双份；webserver 缺目录时明确日志告警。
- 回滚：本改动不触碰 API 行为，回滚仅需恢复 webserver.go 与 vite 配置即可。
