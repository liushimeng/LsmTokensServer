## 一、背景：阶段CX 上线后的实测数据画像

阶段CX 已交付页面骨架（状态卡 / 时延折线 / 热力图 / 错误堆叠柱 / 明细表），
本次**不新增页面**，目标是把「按时间维度展示的服务质量数据」从"能看"提升到"可信、可比较、可下钻"。

在优化前，先对生产库做了完整数据画像（近 7 天、8 张分表全量 39,728 行）：

| 观测项 | 实测结果 | 对 QoS 计算的影响 |
|---|---|---|
| 表结构时间字段 | `request_start_at` / `created_at` / `response_start_at` / `response_end_at`，全部非空 | 时间桶以 `request_start_at` 为准（收到请求时刻），`created_at` 仅用于扫描裁剪 |
| 状态码形态 | `"200 OK"` 39,636 行、`"200"` 9 行、`404`/`401`/`529`/`400`/`403` 共 83 行 | `ParseResponseStatusCode` 可兼容，但**错误请求的 elapsed 极短**（快速失败） |
| 输出 Token 分布 | P10=65、P50=342、P90=5,777、P99=24,523 | 请求体量跨 3 个数量级，**原始时延不可横向比较** |
| 原始时延变异系数 | 同模型内 58% ~ 165% | 抖动率若是"原始时延 CV"，几乎恒定巨大 → 信息量近似为零 |
| 按 Token 分档后 | 分模型拥堵系数 CV 从 31%~659% 降到 30%~189%，中位数落在 0.85~1.00 | **分档归一化是让拥堵系数可比的关键** |
| 同模型多源站 | 单模型对应 1~8 个 `dst_endpoint_id` | 同模型不同源站速率差异大，但页面按模型聚合是既定口径（源站质量差异本身就是信号） |

由此定位出阶段CX 的 6 个**时间维度数据质量问题**：

1. **P1 · 时延统计混入错误请求**：429/5xx 快速失败把 `avg_elapsed_ms`/`p95` 拉低，
   故障越严重、时延反而越低，趋势图会"报喜"。
2. **P2 · 抖动率口径失真**：`标准差/平均时长` 直接对原始 elapsed 计算，
   被请求体量主导（CV 长期 100%+），无法反映排队/网络抖动。
3. **P3 · 拥堵系数的小请求偏置**：`baseline × tokens` 把固定开销（TTFT、建连、
   协议转换）摊到 Token 上，短输出请求（P10=65 tokens）系数天然虚高。
4. **P4 · 未结束时间桶污染对比**：当前小时/当天是进行中的桶，
   直接与完整桶比较会系统性偏低，峰值/告警判断失真。
5. **P5 · 实时窗口一刀切**：固定 5 分钟窗口对低流量模型频繁落入"无流量"，
   状态卡失去意义，也没有任何"样本量/最后请求时间"提示。
6. **P6 · 只有"图"，没有"逐时段明细"**：无法回答"最近 1 天每个小时、
   最近 1 周每一天，各模型具体差在哪"——而这是运维排障的第一入口。

## 二、优化目标与验收口径

| 目标 | 验收标准 |
|---|---|
| 时延口径可信 | 趋势/明细展示的成功时延不含错误请求；错误单独成列/成图 |
| 抖动可解释 | 抖动率 = 拥堵系数变异系数（无量纲），跨模型可比较；样本 < 5 标记低样本 |
| 系数可比 | 按输出 Token 分档（10 档对数分箱）计算基准，短请求不再天然虚高 |
| 时间语义准确 | 进行中桶带 `partial` 标记，前端显式标注"进行中"，不参与峰值误导 |
| 实时窗口鲁棒 | 5 分钟 → 15 分钟 → 60 分钟逐级回退，返回实际窗口与最后请求时间 |
| 逐时段可下钻 | 新增「时段明细」表：近 24 小时逐小时 + 近 7 天逐日，全指标对齐 |

## 三、核心算法升级（相对前置方案 §三）

### 3.1 基准推理速度：Token 分档归一化

前置方案：`baseline = Σelapsed / ΣTokens`（全模型一刀切）。
问题：请求的固定开销（首字节、建连、协议转换）不随 Token 线性增长，
65 tokens 的小请求 `ms/Token` 远高于 24k tokens 的大请求，导致小请求系数虚高。

升级为 **10 档对数 Token 分箱**，每箱独立计算 `Σelapsed/ΣTokens`：

```
边界（输出 tokens）：64,128,256,512,1024,2048,4096,8192,16384,32768
bin(tokens) = bisect_right(EDGES, tokens)          // 0..10
bandBaseline[b] = Σelapsed_b / ΣTokens_b           // 仅 2xx 且 tokens>0、elapsed>0
样本数 < 30 的箱 → 回退全局 baseline（避免小样本噪声）
requestExpected = bandBaseline[bin(tokens)] × tokens
coefficient     = elapsed / requestExpected        // 截断上限 100
```

实测效果（近 7 天全量）：拥堵系数变异系数中位数从 ~180% 降到 ~90%，
中位数系数收敛到 0.85~1.00，卡顿率（系数 > 2.0）从 0%~1% 变为 0.9%~12%，
**阈值 1.2/2.0/5.0 的分档重新具备区分度**。

对外仍保留 `baseline_ms_per_token`（全局 Σ/Σ，前置方案口径）用于展示；
新增 `baseline_bands`（已校准档数）说明归一化覆盖度。

> 局限性（写入文档也是契约）：基准取自近 7 天窗口，若模型在整个窗口持续拥堵，
> 基准会被"污染"，系数趋于 1。因此页面**同时**给出绝对指标
> `ms/Token`（逐时段、逐模型）与 P95 时延，二者结合判断绝对退化。

### 3.2 时延统计：成功/失败分离

每个时间桶同时输出两套时延：

| 字段 | 口径 | 用途 |
|---|---|---|
| `count` / `success_count` | 总请求 / 2xx 请求 | 流量与成功率 |
| `ok_avg_elapsed_ms` / `ok_p50_ms` / `ok_p95_ms` | **仅 2xx** | 趋势图、时段明细、周基准（新增，前端主用） |
| `avg_elapsed_ms` / `p95_elapsed_ms` | 全部请求（保留阶段CX 语义） | 兼容旧字段，前端不再作为主展示 |

### 3.3 抖动率：改为无量纲系数变异系数

```
jitter = stdev(coefficient_i) / mean(coefficient_i) × 100%
```

只统计成功且可算系数的请求；样本 < 2 时为 0。
它等价于"排除请求体量后的时延波动"，能真实反映排队抖动与网络抖动。
原"原始 elapsed CV"字段不再输出（避免误读）。

### 3.4 卡顿率与低样本保护

- 卡顿率 `stall_rate = 系数 > 2.0 的请求数 / 可算系数请求数 × 100%`
- 新增 `coefficient_samples`：前端在样本 < 5 时以 `—` + 低样本提示展示，
  不把单笔样本的 100%/0% 当成结论。
- 进行中时间桶标记 `partial=true`：前端以"进行中"标签与空心端点标识，
  峰值/对比读数不把未结束桶计入。

### 3.5 实时窗口：逐级回退 + 事实字段

前置方案固定 5 分钟。升级为 **5 → 15 → 60 分钟**逐级回退：
取第一个样本数 ≥ 5 的窗口；60 分钟仍无数据则判定 `idle`。
`live.window_minutes` 返回实际窗口，`live.last_request_at_ms` 返回最后请求时间，
状态卡明确写出"近 N 分钟"，避免低流量模型被误标"无流量"。

### 3.6 时间桶对齐与进行中标记

| 视图 | 桶 | 数量 | 进行中桶 |
|---|---|---|---|
| 近 1 小时 | 分钟 | 60 | 当前分钟 |
| 近 24 小时 | 小时 | 24 | 当前小时 |
| 近 7 天 | 自然日 | 7 | 今天 |
| 热力图 | 7 天 × 24 小时 | 168 | 今天当前小时 |

天桶/热力图行索引改用**日期键映射**（`today.AddDate(0,0,-6).Format("2006-01-02")`），
不再用 `Hours()/24` 推导，避免夏令时/跨月边界误差。

### 3.7 逐时段绝对速度

每个时间桶新增 `ok_ms_per_token = Σelapsed(2xx) / ΣTokens(2xx)`：
该值不依赖基准，可直接观察"这一小时/这一天模型是否整体变慢"，
是 3.1 基准自污染问题的兜底视图。

## 六、测试

### 6.1 Go 单元测试（`mysql_http_agent_qos_stats_test.go` 扩展）

1. **Token 分档基准**：小请求（100 tok / 2000ms）与大请求（4000 tok / 20000ms）
   同模型时，小请求系数不会被"5ms/Token 全局基准"放大到 4 倍；
   分档后两笔系数接近（±30%）。
2. **成功时延分离**：同桶 1 笔 200（5000ms）+ 1 笔 429（50ms），

3. **抖动率口径**：桶内系数相同 → jitter=0；系数 [1,2] → CV=33.33%。
4. **进行中标记**：当前分钟/小时/天桶 `partial=true`，历史桶 false。
5. **实时窗口阶梯**：5 分钟无数据、30 分钟前有数据 → `window_minutes=60`
   （15 分钟仍无数据）；`last_request_at_ms` 正确。
6. **低样本字段**：单笔成功请求 `coefficient_samples=1`、`stall_rate` 仍计算但样本可判定。
7. **日期对齐**：7 天序列首尾日期连续、今天 `partial=true`；热力图今天行 = 索引 6。
8. **周成功分位**：错误请求不进入 `week_ok_p50/p95`。
9. 既有用例回归（基准、分档、用户隔离、空库、缓存）。
