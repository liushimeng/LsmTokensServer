## 一、背景与目标

阶段CX 交付页面骨架、阶段CY 修复时间维度数据质量（Token 分档基准 / 成功口径时延 /
低样本保护 / 进行中桶标记 / 逐时段明细）。本阶段聚焦需求剩余的两块：

1. **模型状态总览统计化**：总览不能只有"实时一个点"，要给出各模型源站
   **最近 1 天（逐小时口径汇总）** 与 **最近 1 周（逐日口径汇总）** 的完整统计，
   并以**全模型横向对比图表**呈现质量区别（哪个源站慢、哪个源站爱排队、哪个源站错误率高）。
2. **运行经验预测**：基于近 7 天同时段历史数据（源站的"运行经验"），给出：
   - **下一时段预测**（当前小时 +1 的拥堵系数 / 错误率）
   - **今日剩余时段逐小时预测**
   - **明日预测**（含星期模式加权）
   - **趋势研判**（近 24h vs 前 24h 环比、今日 vs 周均值偏差）
3. **热力图全模型对比**：拥堵热力图从"单模型下拉切换"升级为**全模型小倍数网格**，
   所有源站同屏同色系，质量区别一眼可见（需求明确要求"各个模型一起显示出来，才能看到区别"）。

不新增接口：仍为 `QoSMonitorInterface` 单次扫描，响应结构**只增字段**。

## 三、后端设计（`ServerGo/models/mysql_http_agent_qos_stats.go`）

### 3.1 固定窗口统计 `QoSWindowStats`

```go
type QoSWindowStats struct {
    Window             string  `json:"window"`               // "24h" | "7d"
    Calls              int64   `json:"calls"`
    SuccessRate        float64 `json:"success_rate"`         // %
    AvgCongestion      float64 `json:"avg_congestion"`
    CoefficientSamples int64   `json:"coefficient_samples"`
    StallRate          float64 `json:"stall_rate"`           // %
    Jitter             float64 `json:"jitter"`               // %
    ErrorRate          float64 `json:"error_rate"`           // %
    OkAvgElapsedMs     int64   `json:"ok_avg_elapsed_ms"`
    OkP95Ms            int64   `json:"ok_p95_ms"`
    OkMsPerToken       float64 `json:"ok_ms_per_token"`
}
```

实现：按窗口起点（24h → `now-24h`；7d → 扫描起点）过滤 `m.hours` 的桶键
（`"2006-01-02 15:04"` 字典序 == 时间序），`mergeQoSBuckets` 合并为单一累积器后
走一次 `finalizeQoSBucket` —— 与小时桶/天桶完全同一套口径（分档基准、成功口径、
低样本语义一致），无二次扫描。

`QoSModelReport` 新增 `Stats24h` / `Stats7d` 两个字段（只增不改）。

### 3.2 预测 `QoSPrediction`

```go
type QoSHourForecast struct {
    Hour          int     `json:"hour"`           // 0~23 目标小时
    AvgCongestion float64 `json:"avg_congestion"`
    ErrorRate     float64 `json:"error_rate"`     // %
    Samples       int64   `json:"samples"`        // 历史同小时系数样本总数
    Confidence    string  `json:"confidence"`     // high | medium | low
}
type QoSDayForecast struct {
    Date          string  `json:"date"`           // YYYY-MM-DD
    Weekday       int     `json:"weekday"`        // 0=周日
    AvgCongestion float64 `json:"avg_congestion"`
    ErrorRate     float64 `json:"error_rate"`
    Calls         int64   `json:"calls"`
    Samples       int64   `json:"samples"`
    Confidence    string  `json:"confidence"`
}
type QoSPrediction struct {
    NextHour       QoSHourForecast   `json:"next_hour"`
    TodayRemaining []QoSHourForecast `json:"today_remaining"` // 当前小时+1 ~ 23 时
    Tomorrow       QoSDayForecast    `json:"tomorrow"`
    Trend24h       string            `json:"trend_24h"`       // up | down | flat | unknown
    TodayVsWeek    float64           `json:"today_vs_week"`   // 今日(部分)相对周均值偏差 %
}
```

**算法（可解释、透明，面向运维）**：

1. **同时段历史加权均值**（下一时段 / 今日剩余）：对目标小时 H，取近 7 天每天
   小时桶 H 的平均拥堵系数，按 `coefficient_samples` 加权平均：
   `pred = Σ(avg_i × n_i) / Σn_i`。错误率同理按请求数加权。
   包含今天的进行中小时（其系数是每笔请求的均值，桶未结束不产生偏置，小样本权重自然低）。
2. **星期模式**（明日预测）：近 6 个完整自然天（排除今天）的日均拥堵系数，
   与明天同星期的天权重 ×2（源站通常有明显的 weekday/weekend 模式），
   `pred = Σ(avg_d × n_d × w_d) / Σ(n_d × w_d)`；调用量、错误率同理。
3. **趋势研判**：
   - `trend_24h`：近 24h 加权平均拥堵系数 vs 前 24h（需 48h 数据都在 7 天扫描窗口内），
     比值 > 1.1 → up，< 0.9 → down，否则 flat；任一侧无样本 → unknown。
   - `today_vs_week`：今天（进行中）日均系数 vs 6 个完整天加权均值，
     `(today/full - 1) × 100`；无数据 → 0。
4. **可信度三档**：样本 ≥ 30 → high，≥ 10 → medium，否则 low；
   前端在低可信度时显式标注"仅供参考"。

**工程约束不变**：一次 7 天扫描内完成（预测复用 `m.hours` 全部桶，无需二次扫描）；
keyset 分页、小字段 SELECT、25s context、ctx 取消返回部分结果、NilDB 安全、用户过滤。

## 四、前端设计（`ClientWeb/src/pages/service-quality/`）

### 4.1 状态卡 `QoSCards.jsx`（统计 + 预测行）

- 新增一行**下一时段预测**：`下一时段 {状态分档文字}`，按预测系数四档着色 + 可信度
  （高/中/低）；无历史同小时数据（samples=0）显示灰色"暂无同时段历史"。
- 底部统计行升级为：`近24h {次数} 次 · 错误率 {x}%`（`stats_24h`），保留基准/7天行。

### 4.2 新增 `QoSCompareChart.jsx`（模型质量对比）

- 横向条形图，**窗口（近24h/近7d）× 指标（6 项）双切换**：
  拥堵系数 / 卡顿率 / 错误率 / ms/Token / 成功平均时延 / 成功 P95。
- 按值降序排列，条形右端标数值；模型名取 `modelColor` 稳定分类色。
- 系数/卡顿率/错误率按阈值着色（四档状态色），ms 类指标用中性蓝。
- 系数类指标样本 < 5 的模型：灰条 + `—` + tooltip 低样本说明，不伪造结论。
- 零调用模型不出现在图中（图下脚注说明）。

### 4.3 新增 `QoSForecast.jsx`（运行经验预测）

- 模型选择（与页面 `selectedModel` 联动）。
- **左：今日逐小时折线图** —— 0~23 时：已发生小时画实际系数（当前进行中小时空心点），
  剩余小时画预测（虚线 + 空心点），叠加 1.2/2.0/5.0 阈值虚线；
  tooltip 区分"实际（样本 n）"与"预测（可信度 × · 历史样本 n）"。
- **右：研判面板**：
  - 下一时段预测（大字分档色 + 可信度 + 历史样本数）
  - 明日预测（日期 + 星期、系数、错误率、预计调用量、可信度）
  - 趋势研判（24h 环比 ↑/↓/→ + 幅度；今日 vs 周均值 ±%）
- 无流量模型给出空态文案。

### 4.4 `QoSHeatmap.jsx` 重写（全模型小倍数网格）

- 入参改为 `models / selected / onSelect`：网格 `auto-fill minmax(300px,1fr)`，
  每个模型一块 7×24 迷你热力图（同一四档色标），小时刻度每 6 格、日期标签精简为
  `M-D`；进行中格描边语义不变。
- 悬浮用原生 `title`（小倍数场景避免每层一个 hover 状态）；共享图例行 + 点击选中
  （蓝框，联动时段明细/预测）。
- 原有单模型下拉视图移除（信息是全模型网格的严格子集）。

### 4.5 页面结构（index.jsx）

## 五、测试

### 5.1 Go 单元测试（`mysql_http_agent_qos_stats_test.go` 扩展）

1. **窗口统计**：近 24h 内 1 笔 200（5000ms/100tok）+ 1 笔 429（50ms），
   `stats_24h.calls=2`、`success_rate=50`、`error_rate=50`、`ok_avg_elapsed_ms=5000`；
   `stats_7d` 包含更早数据。
2. **下一时段预测**：昨天同小时 5 笔 1000ms/100tok（系数 1.0），
   `next_hour.hour == (now.Hour()+1)%24`、`avg_congestion≈1.0`、samples=5 → medium。
3. **今日剩余**：长度为 `23 - now.Hour()`，各点 hour 连续递增。
4. **明日预测**：`date == today+1`；完整天数据存在时 congestion > 0、samples > 0；
   无完整天（只有今天数据）时 confidence=low。
5. **趋势研判**：仅近 24h 有数据 → `trend_24h=unknown`；两窗口都有等量数据 → flat。
6. **today_vs_week**：仅今天有数据 → 0；今天系数高于周均值 → 正值。
7. 既有用例回归（分档基准、成功口径、热力图、缓存）。
