# 经济型算法 Session 级负载均衡与源站冷却自动恢复优化方案（阶段AD / v2.0.75）

> 日期：2026-08-25
> 范围：`ServerGo/models/agent_algorithm_economic.go`、`ServerGo/proxy/server_http_ai_proxy_utils.go`、单测两份
> 结论：**纯后端算法层优化，前端与数据库表结构零改动**

---

## 1. 背景与问题定位（实证）

用户反馈：智能路由配置了「经济型」算法，但 claude code / opencode 等 Agent 上没有实现每个新 Session 自动切换与负载均衡。

### 1.1 新旧程序全量对照结论

对旧程序 `/usr/local/LsmHttpAgent/` 与新程序逐文件 diff（Agent 识别、Session 识别、经济型/稳定型算法、转发重试链路）：

| 能力 | 迁移状态 |
|---|---|
| 经济型 livePool 消费 + session 粘性哈希（FNV-1a + 启动时间戳种子） | ✅ 完整迁移 |
| Session 识别（body 多路径 + 多协议头 + OpenClaw/Codex/Grok 专用解析） | ✅ 完整迁移（recognizer 包） |
| 合成 Session（userName+modelName，TTL 15 分钟） | ✅ 完整迁移 |
| Web 增/删源站同步（SyncEconomicRouteEndpoints） | ✅ 完整迁移 |
| 稳定型：列表首源站 + 连续 3 次失败滚动切换（DB 持久化） | ✅ 完整迁移 |
| 重试避开已失败源站（triedEndpoints）、重试清粘性映射（InvalidateSessionMapping） | 🆕 新程序独有增强（v2.0.74） |

**即：Session 级负载均衡的算法本体没有缺失。**

### 1.2 数据库实证（TAgentHttpTransactionDataItem_00，近 14 天）

- claude-cli 的每个 UUID session、opencode 的 `ses_xxx` session **均被正确识别**；在多启用源站的路由上，不同合成 session 确实分布到了不同源站（101/51/12 等），算法运转正常。
- 但 claude-cli 走的路由 9（Anthropic 经济型）源站列表 `129,6,135` 中 **129、6 已是禁用状态**，只剩 135 一个可用源站 → 「负载均衡」无从谈起。

### 1.3 根因

1. **失败摘除是永久性写库删除**：经济型某源站连续失败 3 次（`IsFailoverError` 含 429/500/502/503/504 与网络错误——429 限流是源站常态）→ `RemoveEndpointFromAIRoute` 直接改 DB 路由配置 / 禁用状态，且**没有任何自动恢复机制**。偶发限流的源站被永久剔除，路由池逐渐缩水到单源站，Session 级负载均衡随之失效。
2. **部分 Agent 识别不到 session 又不在合成名单**：线上观测 `atomcode`、`AsyncOpenAI` 等请求 `session_id = unknown_session_id`，不在 `EconomicSyntheticSessionEligibleAgents` 名单 → 落入 `Select()` 兜底固定打第一个源站，同样无法均衡。

## 2. 优化设计

### 2.1 失败摘除改为「内存冷却 + 下一轮自动恢复」（核心）

按用户确认的语义：**连续失败不删除记录，只在负载均衡算法上暂时跳过，保存在内存临时缓存中；等新 Session 循环到下一轮遍历（livePool 重新填充/回收）时自动重试**。

- `economicRouteState` 新增 `cooldownEndpoints map[uint64]time.Time`（内存临时缓存：源站 → 冷却截止时间）。
- 新增 `EconomicEndpointCooldownDuration = 10 * time.Minute`。
- `forwardWithRetry` 收尾从 `RemoveEndpointFromAIRoute`（写库）改为 `CooldownEndpoint`（纯内存）：
  - 从 livePool 摘除、写入冷却表、**清零失败计数**（避免恢复后立即再被摘除）；
  - **不改 DB、不改缓存路由配置**——源站最终去留由管理员在 Web 端决定。
- 自动恢复：`recoverCooldownEndpointsLocked` 在每次 `SelectForSession` / `SelectForKBRequest` 前执行，把到期源站去重后追加回 livePool（校验仍在路由配置中），下一轮分配即可重试。
- 全路径跳过冷却源站：
  - livePool 填充时跳过冷却中的源站；
  - 粘性映射命中冷却源站时清理映射重新分配；
  - 无 session 兜底 `Select()` 跳过；
  - KB 随机分支跳过；
  - `SyncEconomicRouteEndpoints` 增量对齐时不得把冷却中源站加回 livePool，Web 删除源站时同步清掉冷却表项。
- 稳定型算法不动（其滚动切换本来就是 DB 持久化语义）。

### 2.2 合成 Session 名单扩展

`EconomicSyntheticSessionEligibleAgents` 新增：`atomcode`、`asyncopenai`、`claude-cli`、`claude-code`、`kilo-code`、`windsurf`、`cursor`、`copilot`、`pi`、`amp`、`rovo`、`longcat`、`grok-build`、`openclaw`、`openai/js`。
识别不到 session_id 时按 `userName|modelName` 合成（15 分钟 TTL），获得粘性 + 超时轮换均衡，不再固定打第一个源站。

`EconomicAdvancedAgentWhiteList`（KB 分支排除名单）同步补充 `atomcode / asyncopenai / amp / rovo / longcat / grok-build / openclaw`。

## 4. 验证

- `go vet ./...` 通过；`go test ./models/ ./proxy/`（含全量）绿。
- `./rebuild_restart_app.sh` 完整重启，9101/29000 冒烟正常。
- 行为验证路径：多源站经济型路由下，人为使某源站连续失败 3 次 → 日志出现 `cooled down for 10m`（无 DB 删除）→ 10 分钟后出现 `cooldown expired, back to live pool`，新 session 重新可能分配到该源站。

## 5. 风险与回退

- 冷却期间该源站完全不下发流量（与旧行为「永久删除」相比是更保守的临时摘除，风险更低）。
- 回退方式：将 proxy 层 `CooldownEndpoint` 调用换回 `RemoveEndpointFromAIRoute` 即恢复旧行为。
