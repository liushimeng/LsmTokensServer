# 首次运行配置自动回写 + 超级管理员随机生成与禁用机制

> 阶段AL · v2.0.74 · 2026-08-25

## 1. 背景与目标

LsmTokensServer 作为开源 AI Tokens 代理与管理服务，存在两个对新手用户不友好的摩擦点：

1. **首次运行没有任何配置文件** —— 用户必须手动 `cp LsmTokensServer.conf.example LsmTokensServer.conf`，
   还要填 MySQL 密码、JWT 密钥、管理员账号密码、openClaw API Key 等大量字段；填错一项服务直接起不来。
2. **管理端超级管理员账号固定** —— 旧版默认拒绝所有管理端请求（凭证未配置），用户不知道该去哪里设置账号；
   而一旦设置了固定账号密码，对所有用户都是「裸奔」状态，缺乏首次启动时随机生成 + 启动后自动禁用的「
   自我保护」机制。

本次升级目标：

- **首次启动零配置可跑**：检测不到 `LsmTokensServer.conf` 时自动生成完整配置（含合理默认值、随机 JWT 密钥、
  随机超级管理员账号密码、随机 openClaw 占位）；打印醒目的"首次启动"日志摘要到 stdout + `LsmTokensServer.log`，
  并写一份脱敏的 `LsmTokensServer.conf.example` 给用户参考。
- **数据库出现用户记录即锁定超级管理员**：服务启动并完成数据迁移后，探测 `TAgentHttpUserInfo` 表是否有用户；
  若已存在任意用户，把 `security.managerUserName/Password` 回写为字符串 `disable`（保留字段便于运维恢复），
  后续所有管理端登录请求被中间件拒绝（登录页保留可访问，便于管理员说明）。
- **README 多语种提供首次安装部署入口**：在 `README.md / README.en.md / README.ja.md` 顶部"快速启动"
  段落补充"首次启动自动生成配置 + 管理员凭证"小节，并新增"常见问题 → 找不到超级管理员密码？"自助指引。

## 2. 设计要点

### 2.1 配置自动回写（首次启动）

触发条件：**`LsmTokensServer.conf` 不存在** 或 **存在但 JSON 解析失败**。

行为：

1. 在 config 包新增 `EnsureDefaultConfig(path string, force bool) (*LsmTokensServerConfig, bool, error)`：
   - 读取现有 conf（若存在），成功则仅做 `validateAndFixConfig` 修复；
   - 不存在或读取失败时，进入"首次启动"路径：以 `getDefaultConfig()` 为基础，再叠加以下随机值：
     - `security.jwtSecret`：用 `crypto/rand` 生成 32 字节密钥并 base64 编码（与现有 `getJWTSecret` 兼容）；
     - `security.managerUserName`：随机生成 12 位 base32（无歧义字符：去掉 `0/O/1/I/l`），
       形如 `adm-<8位>`，例如 `adm-7kq3m9xp`；
     - `security.managerPassword`：随机生成 16 位 base62（含大小写 + 数字），形如 `K7m9Xp2qR4tN8wY6`；
     - `openClawAPIKey`：空字符串（默认占位，用户自行填写）。
2. 通过 `WriteConfig` 落盘 `LsmTokensServer.conf`，权限 `0600`（`os.Chmod` 兜底，避开 umask 影响）；
   文件模式与现有 `LsmTokensServer.conf` 一致（已 `.gitignore`）。
3. 主进程在 `LoadConfig` 返回后判断"是否是首次启动"，若是则：
   - 在 stdout 打印一段高亮 INFO 摘要，包含"管理员用户名 / 密码 / JWT 密钥"三项**仅一次**（密码只在日志中显示一次，绝不写入 `conf.example`）；
   - 在 `LsmTokensServer.log` 同步记录一次 `LOG_FIRST_RUN` 事件（受 `LOG_USER_ACTION` 已有路径管控）；
   - **不**写入 `LsmTokensServer.conf.example`（避免泄露新生成的真实密钥）。

### 2.2 超级管理员随机生成与禁用

随机生成：见 2.1，`EnsureDefaultConfig` 内完成。

启动后禁用：

1. 主进程在 `LoadConfig` + MySQL 初始化 + 用户表迁移完成后，调用 `models.CountActiveUsers() (int64, error)`；
2. 若返回值 ≥ 1，判定"已被业务接管"，执行 `config.DisableSuperAdmin(path)`：
   - 把 `cfg.Security.ManagerUserName` / `ManagerPassword` 同时设为字符串 `disable`；
   - 把 `cfg.Security.ManagerWebAuthDisabled` 设为 `true`（网关代理部署场景之外的"自动启用放行"开关，
     表示"管理端业务接口全部关闭，登录页可访问"）；
   - 重新写回 `LsmTokensServer.conf`；
   - 在日志里打印一条 `DISABLE_SUPER_ADMIN` 事件。
3. 登录鉴权层（`server_api_manager_login.go`）：
   - 现有逻辑已经把 `ManagerUserName == "" || ManagerPassword == ""` 视为"未配置"；
   - 本次扩展：把 `strings.EqualFold(cfg.Security.ManagerUserName, "disable")` /
     `strings.EqualFold(cfg.Security.ManagerPassword, "disable")` 也视为"已禁用"，登录接口直接返回
     "管理端超级管理员已被禁用，请使用数据库中的业务用户账号登录"，与现有提示文案风格一致。
4. 中间件 `ManagerAuthMiddleware`：
   - 检测到禁用态时，对所有非登录 / 登出 / 验证码路由返回 503 JSON "管理端已禁用"；
   - `/ManagerLoginInterface` 仍可访问（用于前端 SPA 渲染"已禁用"提示），但登录请求被上面的登录
     handler 拒绝。

> 安全边界：禁用是**单向**的——一旦启用 `disable`，后续每次启动即使数据库用户被清空也不会自动恢复；
> 恢复需要管理员手动编辑 `LsmTokensServer.conf` 重置 `managerUserName/managerPassword`。

### 2.3 README 多语种安装入口

`README.md` / `README.en.md` / `README.ja.md` 在"快速启动"段落增加两段：

- **首次启动（First Run / 初回起動）**：3 步跑通
  1. 启动服务（无 `LsmTokensServer.conf` 时自动生成）；
  2. 从启动日志 / `LsmTokensServer.log` 读取管理员用户名和密码；
  3. 打开 `http://127.0.0.1:9101/ManagerLogin` 登录。
- **常见问题 → 忘记管理员密码 / 管理员被禁用**（FAQ）：
  - 编辑 `LsmTokensServer.conf` 的 `security.managerUserName / managerPassword`；
  - 若数据库已有业务用户，被禁用后需重启服务或恢复 conf 后重新启动。

> 三个 README 共用一个一致的章节模板，避免翻译漂移；翻译由 i18n 文案维护。

## 4. 单元测试要点

1. **`TestEnsureDefaultConfig`**：传入不存在的路径 → 返回 `(cfg, true, nil)`，文件已生成、密码长度 ≥ 16 且字符集合法；
2. **`TestEnsureDefaultConfig_PreservesExisting`**：传入已存在的合法 conf → 不覆盖、不修改；
3. **`TestDisableSuperAdmin_RewritesConfig`**：临时 conf + 业务用户存在 → 调用后 `managerUserName == "disable"`、
   `managerWebAuthDisabled == true`；
4. **`TestManagerLogin_Disabled`**：构造禁用态配置，POST `/ManagerLoginInterface` 返回禁用提示；
5. **`TestCountActiveUsers_Empty`**：空表返回 `(0, nil)`；**`TestCountActiveUsers_WithRows`**：插入 1 条软删除 + 1 条有效 → 返回 1。

## 5. 兼容性 & 回滚

- **向后兼容**：旧版用户已部署的 `LsmTokensServer.conf` 不会被覆盖（`EnsureDefaultConfig` 检测到文件存在即跳过）；
- **回滚**：禁用态由 `disable` 标记驱动，把这两个字段改回非 `disable` 值并重启即恢复；不需要 DB 迁移。

## 6. 风险 & 缓解

| 风险 | 缓解 |
|---|---|
| 首次启动时控制台 / 日志泄露密码 | 密码仅在 stdout + 主日志中**一次性**打印，不进 `*.example`，并提示用户立即登录后修改 |
| 误禁用（数据库误判） | 仅以 `TAgentHttpUserInfo` 表非软删除行数判定；启动期单次判定不持久触发，禁用后不会反复写 |
| 文件权限不安全 | 写完 conf 调 `os.Chmod(path, 0600)` 兜底，避开进程 umask 干扰 |
| 旧版本 README 没看到这一节 | 在文档标题上加锚点 `#first-run-setup`，在 README 顶部目录里也补一项 |
