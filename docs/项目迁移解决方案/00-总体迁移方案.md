# LsmTokensServer 项目迁移总体方案

> 版本：v1.0（2026-08-24）
> 旧项目：`/usr/local/LsmTokensServer/LsmTokensServer/`（私有，Go 内嵌 Web，前后端不分离）
> 新项目：`/usr/local/LsmTokensServer/LsmTokensServer`（开源，前后端分离）

## 1. 迁移目标

| 项目 | 旧（LsmTokensServer） | 新（LsmTokensServer） |
|---|---|---|
| 仓库 | 私有 | 开源（gitcode: liusm109117198/LsmTokensServer） |
| 架构 | Go 单体，HTML 内嵌在 Go 代码中 | 前后端分离 |
| 后端 | 根目录平铺 .go 文件 | `ServerGo/`（Go，按基础/业务模块分包） |
| 前端 | 无（Go 拼接 HTML/JS） | `ClientWeb/`（React + Vite） |
| 配置 | `LsmTokensServer.conf` | `LsmTokensServer.conf`（含敏感信息，git 忽略，仅提供模板） |
| 端口 | 9101/29000/29001/29002/29003 | **保持不变**（切换期避免冲突，新程序先只编译不占用端口） |

## 3. 命名与内容改写规则

1. 所有出现 `LsmTokensServer` → `LsmTokensServer`（代码、注释、Markdown、日志文件名、脚本）。
2. Go module：`github.com/lishimeng/LsmTokensServer` → `github.com/lishimeng/LsmTokensServer`。
3. 包名、目录名按新结构科学命名（见上）；文件名保留原语义（如 `server_conf.go` → `config/config.go`）。
4. Markdown 文档：根目录的 `*.md` 迁移至 `docs/` 或 `docs/项目迁移解决方案/`，文件名与内容中的 URL、路径同步改写。
5. 敏感信息检查：`LsmTokensServer.conf`（MySQL 账号密码、openClaw APIKey）、`server.crt`/`server.key`、各类 `.log`、二进制文件，全部加入 `.gitignore`，禁止提交。

## 4. 分阶段计划（每阶段完成即中文 git 提交）

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| 阶段0 | 本方案文档 | 文档齐全并提交 |
| 阶段1 | 工程骨架：目录、ServerGo 空编译通过、ClientWeb 空项目、脚本、.gitignore、docs 迁移 | `go build` 通过、`npm run build` 通过 |
| 阶段2 | 后端基础模块：config/logger/database/models | 编译通过 + 基础单测通过 |
| 阶段3 | 代理/协议/识别器/算法/API 接口层 | 编译通过 + 相关单测通过 |
| 阶段4 | 爬虫/MCP/WebSocket | 编译通过 + 相关单测通过 |
| 阶段5 | 前端页面逐页实现（登录→用户端→管理端） | 页面可访问，接口联调通过 |
| 阶段6 | 测试迁移、全量验证、端口切换 | 全部服务正常后**人工确认**停旧服务 |

## 5. 风险与约束

- **旧服务不中断**：`/usr/local/LsmTokensServer/LsmTokensServer` 持续运行；新程序在功能全部迁移完毕前**只编译不启动占用端口**（脚本默认 build-only，切换时才 restart）。
- **端口冲突**：新旧端口一致，切换必须在同一时间窗口完成（停旧→起新），脚本需支持该流程。
- **数据库共享**：迁移期新旧程序共用同一 MySQL `lsmDB`，新程序切换前不得执行破坏性清理任务（`enableSpiderScheduler=false`、cleanup 任务默认关闭，直至切换完成）。
- **测试用例**：旧工程大量 `v20xx_*_test.go`，按模块归入对应包，随阶段迁移。

## 6. 切换与回滚

1. 阶段6 全量测试通过 → 人工核实清单确认。
2. 执行 `./scripts/rebuild_restart_app.sh`（会停止旧进程、起新进程、验证端口）。
3. 如异常：脚本支持回滚 —— 重启旧目录 `LsmTokensServer` 二进制（旧二进制保留不删）。
