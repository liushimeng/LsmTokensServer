# Web 时间跨度通用组件与动态档位方案（管理员 Web + 用户 Web）

> 日期：2026-08-26
> 范围：`ClientWeb/`（管理员 Web + 用户 Web 双构建）、`ServerGo/`（api / models / websocket）
> 目标：把各查询页面散落的「时间跨度」下拉框抽成一个通用前端组件，档位由配置
> `transactionRetentionDays` 动态决定（最小 1 小时，最大 `transactionRetentionDays + 1` 天，
> 固定 10 档），后端统一时间过滤语义并暴露档位配置接口。

---

## 1. 背景与问题

1. 各统计/分析页面的数据查询（ModelInfo / AgentInfo / ChatAnalysis 系列 / AIRouteManage /
   ProtocolConvertAnalyzer / CleanupReport）基本都基于分表
   `TAgentHttpTransactionDataItem_%02d` 的记录统计。
2. 配置 `LsmTokensServer.conf` 的 `transactionRetentionDays`（默认 45 天，上限 3650 天，
   显式 0 = 禁用清理）决定交易明细最长保留时间；过期数据由清理服务物理删除。
   因此**查询时间跨度远大于保留期没有意义**——查到的只是「剩余数据」而不是完整统计。
3. 现状：9 个页面各自硬编码 `DAYS_OPTIONS`（彼此还不一致），最长固定 90 天 + 「全部」，
   与实际保留期脱节；且多数接口只支持「天」粒度，无法查最近 1/3/6 小时。

### 1.1 现状清单（前端）

| 页面 | 现有档位（days） | 参数语义 | 持久化 |
|---|---|---|---|
| `ModelInfo.jsx` | 1,3,5,7,14,30,60,90,0(全部) | days>0 / 0=全部 | localStorage |
| `AgentInfo.jsx` | 同上 | 同上 | localStorage |

### 1.2 现状清单（后端时间过滤）

* **统一 span 编码已存在但覆盖不全**（v2.0.40/2.0.41 引入）：
  `span==0` 无限制；`span>0` 最近 N 天（`ClampStatsDays` 上限 365）；
  `span<0` 最近 |span| 小时（上限 720）。`models/subtable.go:resolveStatsSpanCutoff`。
* 仅 `AIRouteManage`（batch_stats / count_record_by_protocol）与 `ChatAnalysisInterface`
  （白名单）支持小时；`ModelInfo/AgentInfo stats`、Session/Task/Total、PCA、清理报告
  均只认「天」，负数 span 会被 `ClampStatsDays` 折叠成 0（= 无限制，语义错误）。
* 天粒度 SQL 混用两种写法：`created_at >= DATE_SUB(CURDATE(), INTERVAL ? DAY)`（自然日
  对齐）与 `DATE_SUB(NOW(), ...)`（滚动 24h）；另有 `applyStatsDaysWhere` 用 Go 端
  cutoff 参数（注释明确为避免 MySQL/SQLite 方言差异）。

## 2. 总体设计

### 2.1 统一时间跨度编码（沿用既有约定，不新造字段）

```
span == 0   → 无时间限制（兼容旧「全部」，新 UI 不再提供）
span  > 0   → 最近 span 天     （上限 365，ClampStatsSpan）
span  < 0   → 最近 |span| 小时 （上限 720h = 30 天，ClampStatsSpan）
```

### 2.2 动态档位生成（前端，确定性算法）

* **最小档**：1 小时（span=-1）；**最大档**：`transactionRetentionDays + 1` 天；
  共 **10 档**。
* 上限换算：
  * `retentionDays > 0` → `maxSpanHours = min(retentionDays + 1, 365) * 24`
    （365 为后端统计天上限，超出部分后端会裁剪，前端不再展示）。
  * `retentionDays == 0`（禁用清理，数据永久保留）→ 回落 `365 天`（后端统计上限）。
* **档位算法**：预置「漂亮值」阶梯（小时 `[1,2,3,4,6,8,12,18]`，
  天 `[1,2,3,4,5,7,10,14,21,30,45,60,75,90,120,150,180,270,365]`×24h），
  取开区间 `(1h, maxH)` 内的候选，等距抽取 8 个中间档（`round(i*(n-1)/9)`），
  首尾固定 1h 与 maxH；候选不足时按几何插值补齐，最终去重、严格递增、恰好 10 档。
* 示例（实现值）：retention=30 → `1h, 3h, 6h, 12h, 1d, 3d, 5d, 10d, 21d, 31d`；
  retention=45 → `1h, 3h, 6h, 12h, 1d, 4d, 7d, 14d, 30d, 46d`；
  retention=90 → `1h, 3h, 8h, 18h, 3d, 5d, 14d, 30d, 75d, 91d`；
  retention=0（禁用）→ 上限 365d：`1h, 4h, 12h, 2d, 5d, 10d, 30d, 75d, 150d, 365d`。

### 2.3 配置下发：新接口 `/TimeSpanConfigInterface`

* GET，双端注册：管理端挂 `RegisterManagerAPIRoutes`（自动受 ManagerAuthMiddleware
  保护），用户端挂 `RegisterUserAPIRoutes`（受 userAuthMiddleware 保护，登录后可用）。
* 响应：

```json
{
  "success": true,
  "transaction_retention_days": 45,
  "max_span_days": 46,
  "max_span_hours": 1104,
  "min_span_hours": 1,
  "levels": 10
}
```

* 前端模块级缓存（60s TTL + sessionStorage），多页面共享一次请求。

### 2.4 后端时间过滤统一（span 化）

1. `models/subtable.go`：
   * 新增 `ClampStatsSpan(span int) int`：0 透传；>0 裁到 ≤365；<0 裁到 ≥-720。
   * 新增导出 `SpanCutoffTime(span int) (time.Time, bool)`（= 既有
     `resolveStatsSpanCutoff`，供 websocket 等包复用）。
   * `applyStatsDaysWhere` 升级为 `applyStatsSpanWhere`（cutoff 参数化，span 语义），
     全部调用点迁移。
2. 全部 `DATE_SUB(...)` 字符串 SQL 改为 **Go 端 cutoff 参数化**
   （`created_at >= ?`），顺带消除 MySQL/SQLite 方言差异（单测跑 SQLite）并统一为
   「滚动窗口」语义（`now - N×24h`，与 stats 页既有行为一致；`CURDATE()` 自然日语义
   废弃）。
3. 接口层白名单 → **范围校验**：
   * `normalizeChatAnalysisDays`（api）：合法域 `[-720..-1] ∪ {0} ∪ [1..365]`，非法回落 3。
   * `normalizeChatStatsDays`（websocket ChatTotal WS）：同上，非法回落 7。
   * Session/Task/PCA/Total：透传 span，由模型层换算。
4. `websocket` ChatTotal 流式聚合器：新增 `span` 字段；扫描 WHERE 用
   `SpanCutoffTime(span)`；天槽位展示按 `displayDays = span>0 ? span : ceil(|span|/24)`
   生成（小时窗口落在当天桶内，语义为「今天至今」）。

### 2.5 前端通用组件

1. `ClientWeb/src/shared/timeSpan.js`（纯逻辑，无 React）：
   * `buildSpanLevels(maxSpanHours, levels=10)` → `[{span, hours, label}]`
   * `spanToHours(span)` / `nearestSpan(levels, staleValue)`（旧 localStorage 值就近迁移）
   * `fetchTimeSpanConfig()`（GET + 60s 缓存）
   * `useSpanLevels()` React hook（放 `components/TimeRangeSelector.jsx`，避免 shared
     引 React）
2. `ClientWeb/src/components/TimeRangeSelector.jsx`：
   受控 `<select>`，props `{ span, onChange, levels, loading, label }`；
   档位文案走 i18n（`timeRange.lastNHours / lastNDays / maxWindow`）。
3. 页面接入（9 处 + 趋势面板）：
   * ModelInfo / AgentInfo：stats 请求 days → span；旧 localStorage 值就近迁移。
   * ChatAnalysis / Session / Task / Total / AIRouteManage / ProtocolConvertAnalyzer /
     CleanupReport：替换 DAYS_OPTIONS。
   * `HourlyTrendPanel`：窗口按钮改为动态档位（≤720h 的子集，首档 24h 起）。
4. i18n 三语（zh-CN / en / ja）新增 `timeRange.*` 命名空间，9 个页面复用。

### 2.6 兼容与迁移

* 旧 localStorage（`lsm:*:days:v1`）：读到不在新档位的值 → `nearestSpan` 就近归档
  （0/全部 → 最大档；90 天超上限 → 最大档；3 → 3d 或就近小时档）。
* 后端保留 `span==0`（无限制）语义不删，兼容任何旧客户端请求。
* URL 参数（`?days=`）同样就近迁移。

## 4. 验收标准

1. 管理员 Web（9101）与用户 Web（29001）所有时间跨度下拉均为同一组件、同一动态 10 档
   （1h ~ retention+1d）；修改 `transactionRetentionDays` 重启后档位随之变化。
2. 选 1h/3h 等小时档，ChatAnalysis / stats / Total / PCA / Session / Task 各页查询结果
   的时间范围正确（抽查 SQL 日志或数据时间戳）。
3. `go build ./...`、`go vet ./...`、`go test ./...` 全绿；`npm run build` 双构建通过，
   `dist-user` 无管理端字样（grep 复验）。
4. 旧 localStorage / URL 参数不报错，自动就近归档。
5. `dist-user` 与 `dist-manager` 均包含 TimeRangeSelector（两端共用，非管理端专属）。
