# 对话分析页面内联展开与代码模块化重构方案

> 日期：2026-08-26
> 范围：`ClientWeb/src/pages/ChatAnalysis.jsx` 及相关组件
> 影响：管理员 Web（9101）+ 用户 Web（29001）的 `/ChatAnalysis` 页面

## 1. 背景与问题

### 1.1 现状

- `ChatAnalysis.jsx` 是一个 539 行的单文件平铺组件，包含筛选、表格、详情弹窗、批量删除等全部逻辑。
- 详情展示使用 **Modal 弹窗**，每次只能查看一条记录的详情，无法同时对比多条记录。
- 15+ 个筛选条件 state 全部平铺在组件内部，与业务逻辑耦合。
- 页面目录 `pages/` 下所有页面平铺为单文件，缺乏模块化组织。

### 1.2 目标

1. **删除 Modal 弹窗**，改为表格行内展开详情面板，支持多条记录同时展开对比。
2. **代码结构模块化**：将 ChatAnalysis 从单文件拆分为 `pages/chat-analysis/` 模块目录。
3. **保持所有现有功能**：筛选记忆、按需加载、缓存、批量删除等。
4. **专业 UI 设计**：内联详情面板美观、交互流畅。

## 2. 技术方案

### 2.1 目录结构

```
ClientWeb/src/pages/chat-analysis/
├── index.jsx                    # 主页面组件（筛选+表格+分页）
├── ChatAnalysisToolbar.jsx      # 筛选条件工具栏组件
├── InlineDetailRow.jsx          # 内联展开详情面板（替代 Modal）
├── DetailHeader.jsx             # 详情头部（协议流向+KPI卡片+请求信息）
├── DetailTabs.jsx               # 6字段 Tab 导航（分组式）
├── DetailBody.jsx               # 详情主体渲染（raw/json/sse/agg 4视图）
├── DetailFooter.jsx             # 详情底部状态栏
├── useChatAnalysisFilters.js    # 筛选条件 localStorage 记忆 Hook
├── useChatAnalysisData.js       # 数据查询 + 详情加载 Hook
└── constants.js                 # 常量定义
```

旧文件 `pages/ChatAnalysis.jsx` 改为 1 行 re-export，确保 App.jsx 路由注册不变。

### 2.2 内联展开机制

利用 `DataTable` 已有的 `collapsible` + `collapsedIds` + `onToggleCollapse` + `renderCollapsedRow` API：

- 维护 `expandedIds: Set<id>` 状态
- `collapsedIds` = `expandedIds`（反转语义：在集合中的行用 `renderCollapsedRow` 渲染详情面板）
- 点击"详情"按钮切换 `expandedIds`，支持多条同时展开
- `renderCollapsedRow` 渲染 `InlineDetailRow` 组件

### 2.4 数据加载策略

- 详情数据**按需加载**：点击展开时才调用 `ChatAnalysisDetailInterface`
- **内存缓存**：`detailCache` 对象，key 为 `${rowId}:${field}`
- 支持同时展开多条记录，每条独立加载和缓存

### 2.5 筛选条件 localStorage 记忆

- 存储 key：`lsm:chat_analysis:filters:{manager|user}`
- debounce 300ms 保存
- 页面加载时从 localStorage 恢复，路由参数优先
