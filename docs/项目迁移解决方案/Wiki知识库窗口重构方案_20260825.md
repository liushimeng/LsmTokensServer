# Wiki 知识库窗口重构方案（阶段AG，2026-08-25）

> 背景：管理员/用户 Web 顶部工具栏均提供 `Wiki` 弹窗，阶段 L 迁移至 `ClientWeb/src/components/ToolbarDialogs.jsx` + `ServerGo/api/server_api_common_extra.go::wikiInterfaceHandle`。
> 当前实现仅返回扁平化 `[{path, name}]` 列表 + `get_content` 整文件读取，63 个 Markdown 文件混在一起无层级；前端用一张三列小表（路径/文件名/查看）展示，定位文档效率低，且大文件（>100KB）一次性全量读取 DOM 渲染卡顿。
> 本方案以**目录树**为主体、**惰性分块**加载文件内容、统一管理端/用户端双构建前端、复用阶段AA 路径安全工具，全面提升 Wiki 弹窗的可读性、性能与可维护性。

---

## 1. 现状盘点

### 1.1 后端（`ServerGo/api/server_api_common_extra.go`）

| 函数 | 当前行为 | 局限 |
|---|---|---|
| `getWikiFiles` | `filepath.Walk` 递归扫项目根，扁平收集所有 `.md` | 丢失目录层级；返回 `[{path, name}]` 仅两条字段 |
| `wikiInterfaceHandle`（无 action） | 返回 `{files, count}` | 列表信息贫乏（无大小/修改时间/类型） |
| `wikiInterfaceHandle({action: "get_content", file_path})` | `os.ReadFile` 整文件读，`safeProjectFilePath` 限制 5MB | 大文件全量加载到内存 + JSON 序列化 + 前端 `dangerouslySetInnerHTML` 一次性渲染（50KB 仍可，200KB+ 卡顿明显） |

### 1.2 前端（`ClientWeb/src/components/ToolbarDialogs.jsx::WikiDialog`）

- 一次性拉全量列表（无分页/无搜索）；
- 三列表格 `路径 / 文件名 / 查看`，路径全量 `<code>` 展示，长路径挤压可读性；
- 内容视图：单 Modal 切换 `file=null/list → file={path, content}`，`MarkdownView` 直接 `dangerouslySetInnerHTML` 注入整段 HTML；
- 管理员/用户两套构建产物（`dist-manager` / `dist-user`）共享同一组件，行为一致；
- 无面包屑、无目录树折叠、无大小/时间信息、无搜索过滤。

### 1.3 文档总量与体积

- 63 个 `.md`，单文件最大 50KB（`docs/历史归档/CLAUDE.md`），总 ~700KB。
- 真实瓶颈在**单次加载大文件**（10 万行级内容 Markdown 渲染 DOM 节点爆炸），而非列表本身。

## 2. 设计目标

| 维度 | 目标 |
|---|---|
| **结构** | 树形目录（按 `docs/` 实际层级），左树右详双栏；根节点 = 项目根目录 |
| **信息密度** | 文件/目录节点展示 `名称 / 大小 / 最后修改时间 / 类型徽标`（目录显示子项数） |
| **性能** | 列表一次返回整树（小，<100KB JSON）；文件内容**惰性分块**加载，单块 ≤64KB（按行偏移），渲染时分块切片 |
| **可用性** | 顶部全局搜索（按文件名/路径模糊匹配）、目录树展开/折叠/记忆展开状态、面包屑导航、内容区滚动定位 |
| **安全** | 复用 `safeProjectFilePath`；分块读增加 `offset/limit` 校验（offset≥0、limit∈[1, 256]） |
| **双构建兼容** | 管理员端/用户端共用 `WikiDialog` 组件；不引入仅管理端依赖（确保 `dist-user` Rollup 死代码消除后无管理端字样） |

## 3. 接口设计

### 3.1 列表（`POST /WikiInterface` 无 action 或 `action=list`）

**请求体**：可空 `{}`

**响应体**：
```json
{
  "tree": {
    "name": "LsmTokensServer",
    "path": "",
    "type": "dir",
    "size": 0,
    "modified_time": "2026-08-25T15:55:00+08:00",
    "child_count": 63,
    "children": [
      {
        "name": "README.md",
        "path": "README.md",
        "type": "file",
        "size": 5421,
        "modified_time": "2026-08-24T10:00:00+08:00",
        "child_count": 0
      },
      {
        "name": "docs",
        "path": "docs",
        "type": "dir",
        "size": 0,
        "modified_time": "2026-08-25T15:55:00+08:00",
        "child_count": 63,
        "children": [
          { "name": "INDEX.md", "path": "docs/INDEX.md", "type": "file", "size": 2954, "modified_time": "...", "child_count": 0 },
          { "name": "项目迁移解决方案", "path": "docs/项目迁移解决方案", "type": "dir", "child_count": 15, "children": [...] }
        ]
      }
    ]
  },
  "total_files": 63,
  "total_dirs": 10,
  "scanned_at": "2026-08-25T16:00:00+08:00"
}
```

**约定**：
- `type`: `"dir"` / `"file"` / `"other"`（非 .md 文件归 other 且不收集，但目录里仍出现）；
- `path` 始终为相对项目根的正斜杠路径（`README.md` / `docs/开发指南/AGENT.md`）；
- 仅项目根直系 `.md` 文件与 `docs/` 子树参与收集，沿用阶段AA 排除规则：隐藏目录（`.` 开头）跳过、`go-web-debug-tool` 跳过、`python-generate-image-tool` 跳过（gitlink 实体不在源码根）；
- `modified_time` 使用 RFC3339；目录时间为目录内最大 mtime；
- `child_count` = 直属子项数（文件+目录），目录才有意义。

### 3.2 文件内容分块（`POST /WikiInterface {action: "get_content", file_path, offset, limit}`）

**请求体**：
```json
{
  "action": "get_content",
  "file_path": "docs/项目迁移解决方案/用户日志模块数据库持久化重构方案_20260825.md",
  "offset": 0,    // 起始行号（0-based），默认 0
  "limit": 400    // 本次最多返回多少行，默认 400，上限 4000
}
```

**响应体**：
```json
{
  "path": "docs/项目迁移解决方案/用户日志模块数据库持久化重构方案_20260825.md",
  "name": "用户日志模块数据库持久化重构方案_20260825.md",
  "size": 8421,
  "total_lines": 201,
  "offset": 0,
  "limit": 400,
  "has_more": false,
  "modified_time": "2026-08-25T15:55:00+08:00",
  "content": "..." // UTF-8 文本，offset/limit 限定行范围
}
```

**约定**：
- 文件路径安全校验仍走 `safeProjectFilePath`（`.md` 后缀、路径不越出项目根、文件存在且非目录）；
- 分块大小：**默认 400 行、上限 4000 行**（约 64KB UTF-8 文本，对应 50KB 文档一次即可拉完，200KB 文档分 3-5 块）；
- 旧版无 `offset/limit` 的调用方式：服务端若两个参数都为空，按 `offset=0, limit=400` 兜底返回首块（**行为变更**：原版一次性返回全文，现仅首块；前端 `MarkdownView` 改为分块按需"加载更多"按钮，无限滚动可关闭）；
- `has_more` = `(offset+limit) < total_lines`，前端用其控制"加载更多"按钮显隐；
- 错误响应沿用 `{error: "..."}` JSON 形式。

### 3.3 行为不变项

- 仍受管理端 `ManagerAuthMiddleware` / 用户端 `UserAuthMiddleware` 保护（webserver 层）；
- POST 接受 application/json；GET 视为无参（向下兼容旧调试）；
- 仅扫描项目根 + `docs/` 子树，不暴露 `ServerGo/`、`ClientWeb/src/`、`.git/`、`LsmTokensServer.conf` 等敏感路径。

## 4. 前端设计

### 4.1 弹窗布局（两栏：左树 + 右详）

```
│  Wiki 知识库                                          [ × 关闭 ]   │

│  🔍 [ 搜索文件…                ]   [展开全部] [折叠全部]          │
├────────────────┬─────────────────────────────────────────────────┤
│  ▾ LsmTokensS… │  docs / 项目迁移解决方案 / 用户日志…            │  ← 面包屑
│    ▾ docs      │  ─────────────────────────────────────────────  │
│      ▸ 开发指南 │  # 用户日志模块数据库持久化重构方案                │
│      ▸ 历史归档 │  > 背景：…                                       │
│      ▸ mcp      │  ## 1. 现状                                      │
│      ▾ 项目迁…  │  …                                              │
│        📄 00-…  │  …                                              │
│        📄 01-…  │                                                  │
│        📄 用户… │  [ 加载更多 (剩余 1024 行) ]                       │
│        …        │                                                  │
│      ▸ 协议分析 │                                                  │
│    📄 README.md │                                                  │
│    📄 CLAUDE.md │                                                  │
│                │                                                  │
│  共 63 个文件  │                                                  │
└────────────────┴─────────────────────────────────────────────────┘
```

### 4.2 组件结构

`WikiDialog` 拆为三部分：
- `WikiTree`（左侧树）：受控展开状态、键盘左右键折叠/展开、点击节点高亮、文件节点展示图标（📄/📁）；
- `WikiBreadcrumb`（右上面包屑）：路径段可点击跳转到任一层级目录（清空文件选中态，回到该目录列表视图）；
- `WikiContent`（右下方文件区）：渲染当前选中文件的前 400 行，"加载更多"按钮按 400 行/次累加；空目录视图给出"该目录下暂无文档"提示。

### 4.3 状态机

```
states:
  - 'idle'         初始
  - 'loading-tree' 加载目录树
  - 'tree-error'   树加载失败
  - 'browsing'     树就绪，浏览（无文件选中时右下方显示空状态/欢迎语）
  - 'loading-file' 文件加载中
  - 'view-file'    完整文件视图（分块累加）
  - 'file-error'   文件加载失败
```

### 4.4 关键交互

- **搜索**：输入框 value 实时匹配 `name` 或 `path`（小写不区分），命中节点**自动展开所有祖先**并高亮；清空恢复原展开态；
- **展开/折叠**：树节点点击 ▶/▼ 切换；"展开全部"展开到所有目录；"折叠全部"仅保留根；
- **分块加载**：默认首次 400 行；"加载更多"按钮点击后再请求 `{offset: 已渲染行数, limit: 400}` 拼接；累计到 `total_lines` 时按钮自动隐藏；
- **大文件提示**：单文件 > 50KB 时，文件名旁加橙色 chip "大文件（142KB）"，提示用户按需滚动加载；
- **键盘**：左/右方向键在树节点上切换折叠/展开；Enter 选中文件。

### 4.5 复用与依赖

- `renderMarkdown`（`ToolbarDialogs.jsx` 已有）：继续用于文件内容渲染；
- 不引入第三方 Markdown / Tree 库（保持依赖精简，与现有 Wiki/源码弹窗风格一致）；
- 全部使用 `ClientWeb/src/components/ToolbarDialogs.jsx` 内已有 `Modal` + 自实现树组件，不动全局 CSS（必要时新增 `.wiki-tree` / `.wiki-breadcrumb` 类到 `index.css`，对齐 `.data-table` 配色与字号）。

## 6. 安全与边界

1. **路径越权**：所有 `file_path` 必须通过 `safeProjectFilePath(dir, rel, ".md")`，前置阶段AA 已用 `filepath.Rel` 防前缀碰撞；不再依赖 `HasPrefix`；
2. **大文件 DoS**：`safeProjectFilePath` 限制单文件 ≤ 5MB（不再放宽），分块 `limit ≤ 4000`；
3. **隐藏目录**：`getWikiTree` 沿用阶段AA 排除规则（`.` 开头跳过 + `go-web-debug-tool` + `python-generate-image-tool` 跳过）；
4. **响应缓存**：`setNoCacheHeaders` 保持不变（每次都拿最新树，文档更新可见）；
5. **错误信息**：`{error: "..."}` 不暴露项目绝对路径（使用 `relPath` 而非 `absPath` 在错误信息中）；
6. **鉴权**：管理员端/用户端 mux 已分别套 `ManagerAuthMiddleware` / `UserAuthMiddleware`，无需在 handler 内重复。
