# 管理员 Web 用户名/模型名下拉联动升级方案（20260825）

## 1. 背景与目标

管理员 Web（dist-manager，端口 9101）多处页面的查询条件 `用户名`、`模型名` 目前为**手工输入文本框**，存在：

- 用户名/模型名拼写错误导致查询落空；
- 无法直观看到可选的用户与其名下模型；
- 页面之间（UserManage 跳转带参）回填体验差。

**目标**：遍历管理端所有页面，将"输入用户名/模型名进行查询"的表单控件统一替换为 **List 下拉选择**，并实现 **用户名 → 模型名级联**；下拉数据**每页面生命周期内只查询一次**（页面刷新自动重取），避免点一下查一次。

## 2. 涉及页面盘点

| 页面 | 原控件 | 查询接口 | 改造内容 |
|---|---|---|---|
| `ChatAnalysis.jsx` | 用户名 input(L251)、模型名 input(L252) | ChatAnalysisInterface 系列 | 双下拉 + 级联 |
| `ChatAnalysisSession.jsx` | 用户名 input(L87)、模型名 input(L88) | ChatAnalysisSessionInterface | 双下拉 + 级联 |
| `ChatAnalysisTask.jsx` | 用户名 input(L90)、模型名 input(L91) | ChatAnalysisTaskInterface | 双下拉 + 级联 |
| `ChatAnalysisTotal.jsx` | 用户名 input(L263，可空=全站)、模型名 input(L264，可空) | ChatAnalysisTotalInterface / WS | 双下拉（含"全部"空值项）+ 级联 |
| `ChatDialog.jsx` | 用户名 input(L300) 手输；模型已是 select（按用户拉取） | ChatDialogInterface action=models/config | 用户名改下拉；选择后自动触发既有 loadModels 级联 |
| `ProtocolConvertAnalyzer.jsx` | 已是级联下拉（参考实现） | ProtocolConvertAnalyzerUsers | 不动（可后续统一迁移） |
| `UserManage.jsx` | 输入框为新增/编辑表单，非查询过滤 | UserManageInterface | 不在本次范围 |

**双构建隔离约束（CLAUDE.md 2.5）**：以上页面同时编译进用户端（dist-user）。用户端角色下用户名输入本就隐藏（服务端强制 claims.UserName），模型列表来自 `UserModelListInterface`（fetchMyModels）。因此：
- 下拉数据接口 `UserModelOptionsInterface` **仅注册在管理端路由**（RegisterManagerAPIRoutes），用户端构建只在 `isAdminRole()` 为真时调用；
- 用户端模型下拉选项改用页面已拉的 `fetchMyModels()` 结果，不引入管理端接口调用，保证 dist-user 零管理端代码。

## 3. 后端设计：`UserModelOptionsInterface`

- 新文件 `ServerGo/api/server_api_manager_user_model_options.go`，handler `userModelOptionsInterfaceHandle`。
- **GET** `/UserModelOptionsInterface`，仅注册在 `RegisterManagerAPIRoutes`（routes.go），自动受 ManagerAuthMiddleware 保护。
- 数据来源（两次查询，无 N+1）：
  - `models.GetAllUsers(0, 0)` → 全部用户；
  - `models.GetAllUserModels()` → 全部 user→model 关系行（已存在）。
- 内存按 `UserID` 组装，响应：

```json
{
  "success": true,
  "users": [
    { "user_name": "alice", "model_names": ["m1", "m2"] },
    { "user_name": "bob",   "model_names": ["m3"] }
  ]
}
```

- 不返回 APIKey / 用户 ID 等敏感与冗余字段；响应带 `setNoCacheHeaders`。
- 与既有 `ProtocolConvertAnalyzerUsers`（N+1：每用户一次 GetUserModelsByUserID）语义相同，本接口是通用化替代；旧接口保留不动，避免破坏 ProtocolConvertAnalyzer 页面。

## 4. 前端设计：共享模块 `shared/userModelOptions.js`

- **模块级缓存**：`let cache = null`（Promise 化）。`loadUserModelOptions()` 首次调用发起 GET，之后所有页面/组件复用同一 Promise —— **同一次页面生命周期内只查一次**；浏览器刷新即重建模块，缓存自然失效并重取（满足"刷新清缓存更新数据"）。
- `clearUserModelOptionsCache()`：供 UserManage 等页面在增删改后手动失效（本次预留，页面侧调用点为 UserManage 操作成功后刷新，保持简单：UserManage 不消费该缓存，无需联动失效）。
- `useUserModelOptions()` React Hook：封装加载状态，返回 `{ users, loading }`；仅在 manager 构建下真正请求，user 构建下直接返回空（配合 `__APP_ROLE__` 门控，Rollup DCE 后 dist-user 不含该接口字样）。
- 级联规则（各页面统一）：
  - 用户名 select onChange → 清空模型名（ChatDialog 除外，改为自动触发 `loadModels(新用户)` 拉取该用户模型 + 掩码 Key）。
  - 模型 select 选项 = 当前选中用户的 `model_names`；未选用户时（仅 ChatAnalysisTotal 允许）显示全站模型并集。
  - 必填页面（ChatAnalysis/Session/Task）首项为"请选择用户/请选择模型"空值项；可空页面（Total）首项为"全部用户/全部模型"。
