# 对话分析记录查看器升级方案（字段裁剪 / 查找遍历 / 全屏 / 所见即所得复制 / JSON 折叠修复 / 大文本复制兜底）

> 日期：2026-08-27（v2.0.7x 阶段AR）
> 范围：管理员 Web 服务（9101）与用户 Web 服务（29001）共用的 `/ChatAnalysis` 对话分析页面
> 状态：已实施（合并提交）

## 1. 背景与目标

`/ChatAnalysis` 页面的记录详情（内联展开面板）当前展示 6 个字段 Tab，其中
`request_src_protocol_body` / `response_src_protocol_body`（协议转换前的原始报文）因协议转换功能尚未真正启用，内容冗余且误导用户。

本次升级目标：

1. **字段裁剪**：详情仅展示核心数据表 `TAgentHttpTransactionDataItem` 的 4 个字段——
   `RequestHeaders`、`RequestBody`、`ResponseHeaders`、`ResponseBody`；
   不再展示 `RequestSrcProtocolHeaders`、`RequestSrcProtocolBody`、`ResponseSrcProtocolHeaders`、`ResponseSrcProtocolBody`。
2. **四种视图**：每条记录支持 `原文` / `JSON 美化` / `SSE 解析` / `聚合解析`。
3. **JSON 美化可折叠**：`RequestBody`/`ResponseBody` 的 JSON 美化视图以可折叠对象树展示，便于查找、复制。
4. **查找遍历**：所有视图支持关键词查找，匹配高亮、上一个/下一个遍历、匹配计数。
5. **全屏浏览**：详情面板支持进入/退出全屏（Esc 可退出）。
6. **所见即所得复制**：可复制 `原文` / `JSON 美化` / `SSE 解析` / `聚合解析` 当前视图的全部内容。
7. **只读**：所有内容区均为只读渲染（不可编辑），但可选择、复制。
8. **JSON 折叠/展开按钮全量可用**：阶段AR 修复——根级容器不再用 `<details>` 包裹，确保每个对象/数组节点都有独立可见可点的折叠按钮（修复前只有根容器一个 summary，深层折叠按钮不可见）。
10. **复制兜底兼容大文本**：阶段AR 新增 `clipboard.js`，`navigator.clipboard.writeText` 失败时自动回退到 textarea + execCommand 方案，兼容非安全上下文与权限被拒场景，Request Body 等数十万字符也能稳定复制。

### 2.2 需要改造的点

1. 前端 `DETAIL_FIELDS` 含 2 个 `*_src_protocol_body` 字段，`DetailTabs` 有「原始体」分组——已移除。

## 3. 方案设计

### 3.1 字段裁剪（前端 + 后端双侧收口）

- `pages/chat-analysis/constants.js`：`DETAIL_FIELDS` 精简为 4 项
  `request_headers` / `request_body` / `response_headers` / `response_body`。
- `ServerGo/models/subtable.go`：白名单移除两个 `*_src_protocol_body` 键，接口收到旧字段名将返回"不支持的字段"错误。
- `DetailTabs.jsx`：分组改为「请求」（request_headers + request_body）与「响应」（response_headers + response_body）两组；视图子 Tab 仅 body 字段显示。
- i18n 三语言清理：`chatAnalysis.rawBody` / `chatAnalysis.requestSrcProtocolBody` / `chatAnalysis.responseSrcProtocolBody` / `chatAnalysis.forwardBody` 移除。

### 3.2 视图文本统一表示（查找与复制共用）

`ClientWeb/src/shared/viewText.js`：

```js
buildViewText(tab, view, value) => string
```

- headers / 原文视图：原样返回；
- JSON 美化：`prettyJSON(value)`；
- SSE 解析：`sseEventsToText(parseSSEEvents(value))`；
- 聚合解析：`aggregateToText(aggregateSSE(value))`。

`InlineDetailRow` 的复制逻辑与 `DetailBody` 的查找高亮均改用该函数，保证**复制内容 = 查找范围 = 所见**。

### 3.3 查找遍历

两个共享组件（`components/SearchBar.jsx`、`components/HighlightText.jsx`）：

- `SearchBar.jsx`：查找输入框 + 上一个/下一个 + 匹配计数 i/N + 关闭。
  Enter = 下一个，Shift+Enter = 上一个；输入变化自动重置到第 1 个匹配。
- `HighlightText.jsx`：只读高亮文本渲染，对文本按关键词（大小写不敏感）切分，
  匹配段渲染为 `<mark>`，当前匹配项加 `mark-active` 样式并 `scrollIntoView({block:'center'})`；
  通过 `onCount(n)` 回调上报匹配总数供 SearchBar 显示。

交互规则（`DetailBody` 内）：

- 查找词为空：按当前视图正常渲染（JSON→折叠树、SSE→事件卡片、聚合→聚合面板、原文→`<pre>`）。
- 查找词非空：切换为 `HighlightText` 高亮文本模式，文本来源为 `buildViewText(tab, view, value)`。
  这样 JSON 折叠树中被折叠的节点内容也能被检索到，SSE/聚合视图同样可全文遍历。
- 切换字段 Tab 或视图时保留查找词并重新匹配。

### 3.4 全屏

- `InlineDetailRow` 头部工具栏有 `全屏` 按钮；点击后面板根节点追加 `inline-detail-fullscreen` 类：
  `position: fixed; inset: 0; z-index: 1000;` 占满视口，面板内部自滚动，`document.body` 锁定背景滚动。
- 退出途径：再次点击按钮（文案变为 `退出全屏`）、点击 `✕` 关闭按钮、按 `Esc`。
- 收起详情行时自动复位全屏状态。
- 采用 CSS fixed 覆盖层而非 Fullscreen API：无浏览器权限弹窗、行为可控、兼容性好。

### 3.5 复制（所见即所得）

- 复制内容固定为 `buildViewText(tab, view, value)`，与当前视图展示一致。
- 复制按钮位于详情工具栏（与查找、全屏并列），底部状态栏保留元信息（字段/视图/大小/行数）。
- 阶段AR 新增 `ClientWeb/src/shared/clipboard.js`：
  - 优先 `navigator.clipboard.writeText`；
  - 失败兜底：动态创建隐藏 `<textarea>` + `document.execCommand('copy')`；
  - 兼容非安全上下文、权限被拒场景；大文本（数十万字符）也能稳定复制。
- `navigator.clipboard.writeText` 成功后按钮短暂显示 `已复制 ✓`。

### 3.6 只读保证

- 全部内容渲染使用 `<pre>` / `<div>` / `<details>` 非编辑元素，无 `contentEditable`、无 `<textarea>`；
- 用户可选择文本、复制，但无法修改记录内容。

### 3.7 JSON 折叠/展开按钮全量可用（阶段AR 修复要点）

**根因**：`JsonTree.jsx` 早期实现对 `buildJsonTreeNodes` 返回的**根级唯一 NODE_KIND_CONTAINER 节点**用 `<details>` 包裹，导致：

1. 整棵树只有一个顶层 `<summary>`（即"第一个元素"的折叠按钮），其他对象/数组节点的 `<summary>` 都被根 `<details>` 嵌套在 body 内，肉眼看不到独立的折叠按钮；
2. 点击根 summary 会一次性折叠/展开整棵树，无法精细控制单个节点。

**修复**（`ClientWeb/src/components/JsonTree.jsx` + `ClientWeb/src/index.css`）：

1. 根级唯一容器节点**不**渲染为 `<details>`，直接展开渲染其 children，每个深层对象/数组独立渲染自己的 `<details>` 折叠按钮。
2. CSS 调整：`.json-tree summary` 显式设置 `list-style: disclosure-closed` + `display: list-item`，确保 Chromium / Firefox / Safari 都显示原生三角箭头（Safari 默认 `<details>` 的 summary 不一定显示 marker）。
3. `renderChild` 不再包裹额外 `.json-tree-row`，避免破坏 children 嵌套层级。
4. 新增 `ClientWeb/src/shared/jsonTree.test.js`，断言 `buildJsonTreeNodes` 对 `Object{3}` 根节点返回 3 个独立 children（a/b/d），且每个容器 child 都有自己的 `NODE_KIND_CONTAINER` 子节点，确保渲染后存在 3 个独立的 `<details>` summary。

**效果**：

- 任意对象 `{key: {nested: ...}}` 的每一个 `{}` 或 `[]` 都有独立可见可点的折叠按钮；
- 折叠 A 不会折叠 B，符合"每个元素都能独立折叠/展开"的用户预期；
- 配合查找模式可同时检索折叠树中所有层级的内容（折叠时通过 HighlightText 遍历文本，展开时通过 DOM summary 直接定位）。

## 6. 风险与回滚

- 后端白名单收窄后，旧前端（缓存页面）请求 src_protocol 字段会得到 400 错误——双构建与后端同脚本发布，浏览器强刷即可；错误有明确提示，无副作用。
- 全部改动为展示层 + 白名单常量 + 渲染逻辑，无数据迁移；回滚直接 `git revert`。
