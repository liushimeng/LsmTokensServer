# 对话分析记录查看器升级方案（字段裁剪 / 查找遍历 / 全屏 / 所见即所得复制）

> 日期：2026-08-27
> 范围：管理员 Web 服务（9101）与用户 Web 服务（29001）共用的 `/ChatAnalysis` 对话分析页面
> 状态：待实施

## 1. 背景与目标

`/ChatAnalysis` 页面的记录详情（内联展开面板）当前展示 6 个字段 Tab，其中
`request_src_protocol_body` / `response_src_protocol_body`（协议转换前的原始报文）因协议转换功能尚未真正启用，内容冗余且误导用户。

本次升级目标：

1. **字段裁剪**：详情仅展示核心数据表 `TAgentHttpTransactionDataItem` 的 4 个字段——
   `RequestHeaders`、`RequestBody`、`ResponseHeaders`、`ResponseBody`；
   不再展示 `RequestSrcProtocolHeaders`、`RequestSrcProtocolBody`、`ResponseSrcProtocolHeaders`、`ResponseSrcProtocolBody`。
2. **四种视图**：每条记录支持 `原文` / `JSON 美化` / `SSE 解析` / `聚合解析`（已具备，保留并修复细节）。
3. **JSON 美化可折叠**：`RequestBody`/`ResponseBody` 的 JSON 美化视图以可折叠对象树展示，便于查找、复制（已具备 `JsonTree`，保留）。
4. **查找遍历**：所有视图支持关键词查找，匹配高亮、上一个/下一个遍历、匹配计数。
5. **全屏浏览**：详情面板支持进入/退出全屏（Esc 可退出）。
6. **所见即所得复制**：可复制 `原文` / `JSON 美化` / `SSE 解析` / `聚合解析` 当前视图的全部内容。
7. **只读**：所有内容区均为只读渲染（不可编辑），但可选择、复制。

## 2. 现状分析

### 2.1 已具备的能力（复用）

| 能力 | 位置 |
|---|---|
| 四视图渲染 | `ClientWeb/src/pages/chat-analysis/DetailBody.jsx` |
| SSE 解析/聚合纯函数 | `ClientWeb/src/shared/sse.js`（`parseSSEEvents` / `aggregateSSE` / `sseEventsToText` / `aggregateToText`） |
| JSON 折叠树 | `ClientWeb/src/components/JsonTree.jsx` + `ClientWeb/src/shared/json.js`（`buildJsonTreeNodes`） |
| 视图文本化（复制用） | `InlineDetailRow.jsx` 的 `getShownContent()` |
| 详情字段按需加载 + 内存缓存 | `useChatAnalysisData.js` 的 `loadDetail` |
| 后端字段白名单 | `ServerGo/models/subtable.go` 的 `chatAnalysisDetailFieldColumns` |

### 2.2 需要改造的点

1. 前端 `DETAIL_FIELDS` 含 2 个 `*_src_protocol_body` 字段，`DetailTabs` 有「原始体」分组——需移除。
2. 后端白名单 `chatAnalysisDetailFieldColumns` 含同样 2 个字段——需移除（管理端/用户端 `ChatAnalysisDetailInterface` 共用该白名单；`ProtocolConvertAnalyzerRecordDetail` 走独立接口，不受影响）。
3. 无查找功能、无全屏功能——新增。
4. 复制按钮在底部状态栏，查找/全屏无入口——新增工具栏。

## 3. 方案设计

### 3.1 字段裁剪（前端 + 后端双侧收口）

- `pages/chat-analysis/constants.js`：`DETAIL_FIELDS` 精简为 4 项
  `request_headers` / `request_body` / `response_headers` / `response_body`。
- `ServerGo/models/subtable.go`：白名单移除两个 `*_src_protocol_body` 键，接口收到旧字段名将返回"不支持的字段"错误（前后端同步发布，无兼容窗口问题）。
- `DetailTabs.jsx`：分组改为「请求」（request_headers + request_body）与「响应」（response_headers + response_body）两组；视图子 Tab 仅 body 字段显示。
- i18n 三语言清理：`chatAnalysis.rawBody` / `chatAnalysis.requestSrcProtocolBody` / `chatAnalysis.responseSrcProtocolBody` / `chatAnalysis.forwardBody`（仅 DetailTabs 引用，改后无引用）。

### 3.2 视图文本统一表示（查找与复制共用）

新增 `ClientWeb/src/shared/viewText.js`：

```js
buildViewText(tab, view, value) => string
```

- headers / 原文视图：原样返回；
- JSON 美化：`prettyJSON(value)`；
- SSE 解析：`sseEventsToText(parseSSEEvents(value))`；
- 聚合解析：`aggregateToText(aggregateSSE(value))`。

`InlineDetailRow` 的复制逻辑与 `DetailBody` 的查找高亮均改用该函数，保证**复制内容 = 查找范围 = 所见**。

### 3.3 查找遍历

新增两个共享组件（放置于 `components/`，供后续其它页面复用）：

- `SearchBar.jsx`：查找输入框 + `上一个` / `下一个` / `匹配计数(i/N)` / `关闭`；
  Enter = 下一个，Shift+Enter = 上一个；输入变化自动重置到第 1 个匹配。
- `HighlightText.jsx`：只读高亮文本渲染。对文本按关键词（大小写不敏感）切分，
  匹配段渲染为 `<mark>`，当前匹配项加 `mark-active` 样式并 `scrollIntoView({block:'center'})`；
  通过 `onCount(n)` 回调上报匹配总数供 SearchBar 显示。

交互规则（`DetailBody` 内实现）：

- 查找词为空：按当前视图正常渲染（JSON→折叠树、SSE→事件卡片、聚合→聚合面板、原文→`<pre>`）。
- 查找词非空：切换为 `HighlightText` 高亮文本模式，文本来源为 `buildViewText(tab, view, value)`。
  这样 JSON 折叠树中被折叠的节点内容也能被检索到，SSE/聚合视图同样可全文遍历。
- 切换字段 Tab 或视图时保留查找词并重新匹配。

### 3.4 全屏

- `InlineDetailRow` 头部工具栏新增 `全屏` 按钮；点击后面板根节点追加 `inline-detail-fullscreen` 类：
  `position: fixed; inset: 0; z-index: 1000;` 占满视口，面板内部自滚动，`document.body` 锁定背景滚动。
- 退出途径：再次点击按钮（文案变为 `退出全屏`）、点击 `✕` 关闭按钮、按 `Esc`。
- 收起详情行时自动复位全屏状态。
- 采用 CSS fixed 覆盖层而非 Fullscreen API：无浏览器权限弹窗、行为可控、兼容性好。

### 3.5 复制（所见即所得）

- 复制内容固定为 `buildViewText(tab, view, value)`，与当前视图展示一致；
- 复制按钮上移至详情工具栏（与查找、全屏并列），底部状态栏保留元信息（字段/视图/大小/行数）。
- `navigator.clipboard.writeText` 成功后按钮短暂显示 `已复制 ✓`。

### 3.6 只读保证

- 全部内容渲染使用 `<pre>` / `<div>` / `<details>` 非编辑元素，无 `contentEditable`、无 `<textarea>`；
- 用户可选择文本、复制，但无法修改记录内容。

## 5. 验证方案

1. `go build ./...` + `go test ./...`（后端白名单用例）。
2. 前端 `npm run test`（vitest，含新增 viewText 用例）+ `npm run build` 双构建。
3. 双构建隔离复验：`grep -r "ManagerLogin\|UserManage" ClientWeb/dist-user` 无输出。
4. `grep -r "src_protocol" ClientWeb/dist-manager/js ClientWeb/dist-user`（ChatAnalysis 相关字串）确认界面不再出现原始协议字段入口。
5. `./rebuild_restart_app.sh` 完整重启后手工验证：
   - 详情只有 4 个字段 Tab（请求头/请求体/响应头/响应体）；
   - 4 视图切换正常，JSON 树可折叠；
   - 查找：输入关键词高亮、Enter/Shift+Enter 遍历、计数正确；
   - 全屏进入/退出（按钮 + Esc）；
   - 复制内容与当前视图一致；
   - 内容区不可编辑。

## 6. 风险与回滚

- 后端白名单收窄后，旧前端（缓存页面）请求 src_protocol 字段会得到 400 错误——双构建与后端同脚本发布，浏览器强刷即可；错误有明确提示，无副作用。
- 全部改动为展示层 + 白名单常量，无数据迁移；回滚直接 `git revert`。
