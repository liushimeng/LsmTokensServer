# 模型信息 / Agent 信息页面：用户名+模型名筛选与查询统计+记忆功能升级方案

> 版本：v2.0.78 / 阶段 BV
> 日期：2026-09-07
> 范围：`/ModelInfo` 与 `/AgentInfo` 页面（管理端 9101 + 用户端 29001 双构建）
> 参考：`/ChatAnalysis` 页面的用户名/模型名筛选与记忆实现（v2.0.66 阶段 AY 引入）

---

## 一、背景与目标

`/ModelInfo`、`/AgentInfo` 是统计类页面（KPI 卡 + 调用/Token 趋势 + 明细表），目前仅按 `days` 时间档位过滤：

- **管理端**：`ModelInfoInterface` / `AgentInfoInterface` 全站聚合（无 user/model 过滤维度）
- **用户端**：仅本人聚合（从 JWT claims 取 user_name），且用户模型范围来自 `GetUserModelsByUserID(claims.UserID)`

这与 `/ChatAnalysis`（对话分析）的过滤粒度不匹配。对话分析已支持「用户名 + 模型名」联动下拉 + `days` + 多条件筛选 + localStorage 记忆，业务方要求把相同能力复用到 ModelInfo / AgentInfo 上：

1. **管理端**：可选 `user_name`（下拉）+ `model_name`（下拉，按用户名级联），与现有全站聚合**互斥**：
   - 不指定 → 全站聚合（保持现有行为）
   - 指定 → 仅聚合该用户该模型（看单用户单模型视角）
2. **用户端**：仅 `model_name`（从本人模型列表选）
3. **`days` 时间档位记忆**与对话分析保持一致（localStorage 按角色隔离 key）
4. **i18n 三语**齐全

## 二、目标功能详细说明

### 2.1 用户名/模型名 List 列表

复用现有 hooks（已存在，无需新建）：

- 管理端：`useUserModelOptions()`（`ClientWeb/src/shared/userModelOptions.js`）
  - 数据源：`UserModelOptionsInterface`（admin 路由）
  - 字段：`{user_name, model_names:[...]}`
  - 用户名变更时清空 model_name（联动），与 ChatAnalysis 工具栏一致
- 用户端：`useMyModelNames()`（同上文件）
  - 数据源：`UserModelListInterface`
  - 字段：`string[]`
  - 用户端不展示用户名选择器（登录态即身份）

### 2.2 查询统计与展示

| 场景 | summary 调用 | 趋势 | 模型/Agent 明细 |
| --- | --- | --- | --- |
| 管理员 + 不指定 user/model | `GetXxxInfoUsageStatsAll` | `GetHourlyTrendAll` | 全站聚合（当前行为） |
| 管理员 + 指定 user + 指定 model | 新增 `GetXxxInfoUsageStatsByUserModel` | 新增 `GetHourlyTrendByUserModel` | 单一模型视角 |
| 管理员 + 指定 user（不指定 model） | 不支持（保留旧行为）：仍全站聚合 | 同左 | 同左 |
| 用户端 + 不指定 model | 本人全模型（当前行为） | 本人全模型 | 本人全模型 |
| 用户端 + 指定 model | 本人该模型（细化） | 本人该模型 | 本人该模型 |

> 注：**admin 仅指定 user 不指定 model** 这一组合不实现（与对话分析对齐——chat-analysis 也是要求 user+model 同时指定才查，避免大表扫描失控）。如果指定 user 但未指定 model，自动回退全站聚合。

### 2.3 记忆功能（localStorage）

参考 `useChatAnalysisFilters`（`ClientWeb/src/pages/chat-analysis/useChatAnalysisFilters.js`），按角色隔离：

```
admin:  lsm:model_info:filters:manager   / lsm:agent_info:filters:manager
user :  lsm:model_info:filters:user      / lsm:agent_info:filters:user
```

记忆字段：`userName`、`modelName`、`days`。debounce 300ms 写入，与 chat-analysis 一致。

- `userName`、`modelName`：路由 query > localStorage > 默认空
- `days`：路由 query > localStorage > 动态档位最近档（3 天）

## 三、后端方案

### 3.1 新增 model 层函数

#### 3.1.1 `GetModelInfoUsageStatsByUserModel`

文件：`ServerGo/models/subtable.go`

签名：

```go
func GetModelInfoUsageStatsByUserModel(userName string, modelName string,
    subTableNum int, days int) (*ModelInfoUsageSummary, []ModelInfoUsageStat, error)
```

行为：

- 按 `(userName, modelName)` 路由到对应分表（`GetAgentHttpTableName`）
- 单分表聚合 `dst_model_name` 维度（与现有 `GetModelInfoUsageStatsByUser` 一致，但只查一个 model）
- `user_count` 固定为 1（单用户视角）
- 复用 `finalizeModelInfoUsageStats` 计算 share

#### 3.1.2 `GetAgentInfoUsageStatsByUserModel`

文件：`ServerGo/models/mysql_http_agent_info_stats.go`

签名：

```go
func GetAgentInfoUsageStatsByUserModel(userName string, modelName string,
    subTableNum int, days int) (*AgentInfoUsageSummary, []AgentInfoUsageStat, error)
```

行为：按 `(userName, modelName)` 定位分表，按 `agent_tool_name` 聚合。

#### 3.1.3 `GetHourlyTrendByUserModel`

文件：`ServerGo/models/mysql_http_agent_all_stats.go`

签名：

```go
func GetHourlyTrendByUserModel(userName string, modelName string,
    subTableNum int, hours int) (*HourlyTrendResult, error)
```

行为：按 `(userName, modelName)` 定位分表，复用现有 hour-bucket SQL（与 `GetHourlyTrendByUser` 同结构，单 model 版本）。

### 3.2 扩展接口请求体

#### 管理端 `ModelInfoInterface` / `AgentInfoInterface`

现有：

```go
type req struct {
    Action string `json:"action"`
    Days   int    `json:"days"`
    Hours  int    `json:"hours"`
}
```

扩展为：

```go
type req struct {
    Action    string `json:"action"`
    Days      int    `json:"days"`
    Hours     int    `json:"hours"`
    UserName  string `json:"user_name"`  // 新增：管理员可指定 user_name
    ModelName string `json:"model_name"` // 新增：可指定 model_name
}
```

`stats` / `trend` 分支路由：

| Action | UserName | ModelName | 路由 |
| --- | --- | --- | --- |
| stats | "" | "" | `GetXxxInfoUsageStatsAll`（保留旧行为） |
| stats | 非空 | 非空 | `GetXxxInfoUsageStatsByUserModel` |
| trend | "" | "" | `GetHourlyTrendAll` |
| trend | 非空 | 非空 | `GetHourlyTrendByUserModel` |

> 仅 userName 非空、modelName 为空 → 仍走全站聚合（与对话分析对称：user/model 必须同时给才过滤）。

#### 用户端 `ModelInfoInterface` / `AgentInfoInterface`

用户端扩展同样字段，但 `user_name` 由 JWT claims 强制覆盖（防止前端伪造越权）：

```go
if claims.UserID == 0 { /* 未登录 */ }
effectiveUserName := claims.UserName
effectiveModelName := strings.TrimSpace(req.ModelName)
// stats 路由：
//   modelName=="" → GetXxxInfoUsageStatsByUser（本人全模型，现有行为）
//   modelName!="" → GetXxxInfoUsageStatsByUserModel（本人该模型）
// trend 路由：
//   modelName=="" → GetHourlyTrendByUser（现有行为）
//   modelName!="" → GetHourlyTrendByUserModel（新增）
```

注意：用户端"我的模型信息列表"（`action=list`）与"目标源站模型统计"（`dst_summary`）的逻辑不变——这两个 action 只反映本人全量，不随 modelName 过滤。

## 四、前端方案

### 4.1 目录结构

将单文件 `ModelInfo.jsx` / `AgentInfo.jsx` 拆为目录（与 `chat-analysis/` 对齐），但保留改动最小原则：

```
ClientWeb/src/pages/
├── model-info/
│   ├── index.jsx              # 主组件（从 ModelInfo.jsx 迁移）
│   ├── useModelInfoFilters.js # 筛选+记忆 hook
│   └── ModelInfoToolbar.jsx   # 用户名/模型名/时间档位 + 查询按钮
└── agent-info/
    ├── index.jsx              # 主组件（从 AgentInfo.jsx 迁移）
    ├── useAgentInfoFilters.js
    └── AgentInfoToolbar.jsx
```

> 如未来需要更细化（详情块、内联展开等），可参考 chat-analysis 子模块拆分。当前阶段保留单文件即可，仅抽出两个 hook + toolbar 组件。

### 4.2 filters hook

`useModelInfoFilters` / `useAgentInfoFilters` 共享同一份模板（可考虑抽到 `shared/useStatsFilters.js` 再被两者复用）：

- 状态：`userName`、`modelName`、`days`
- 加载流程：
  - 路由 query > localStorage > 默认空（user/model）
  - `days`：动态档位加载后从 saved/默认 3 天就近迁移
- 记忆：debounce 300ms 写入 `lsm:<page>:filters:<role>` JSON
- 仅导出需要的 setter

### 4.3 Toolbar 组件

- 管理端：`<user> <model> <timeRange> <queryButton>` + `__APP_ROLE__ === 'manager'` 守卫
- 用户端：`<model> <timeRange> <queryButton>`（无 user 选择器）
- 用户名变更 → 清空 model（与对话分析一致）
- 模型名选项来源：`isAdmin ? modelNamesOf(userOptions, userName) : myModelNames`
- 时间档位复用 `TimeRangeSelector` + `useTimeSpanLevels`

### 4.4 主组件改造点

- 用 `useModelInfoFilters` 替换原 `useState(userName)` / `useState(modelName)` 散装写法
- 用 `useUserModelOptions` / `useMyModelNames` 注入下拉
- `loadStats(d)` 改为接收 `{days, userName, modelName}` 对象
- `useEffect`：档位就绪后自动首查；user/model 变化后自动重新查询（与 chat-analysis 同样的自动触发语义）
- KPI 卡 / 趋势图 / 模型明细表保持现有渲染

### 4.5 双构建隔离

- 页面源码在 `src/pages/` 下既不属于 manager-only，也不属于 user-only，是双端共用
- 通过 props.route 等上下文判断角色
- i18n key 三语共用
- 不涉及 `__APP_ROLE__` 守卫（这两个页面两端都有入口）

> 注意验证：管理员专属能力（如 `UserModelOptionsInterface` 调用）在用户端构建产物中是否能被 Rollup tree-shake 掉？答案：能。`useUserModelOptions` 内部 `if (__APP_ROLE__ !== 'manager') return`，构建时被 Rollup 直接 dead-code eliminate。

## 七、回退方案

- 后端新函数不影响现有路径（条件分支），回退即弃用 `user_name`/`model_name` 字段
- 前端旧 `ModelInfo.jsx` / `AgentInfo.jsx` 可通过路由回切（临时修改导入路径）
- localStorage 新 key 与旧 key 不冲突，无需迁移

---

## 八、安全考量

- **JWT 越权防护**：用户端强制以 `claims.UserName` 为准，前端传的 `user_name` 字段仅作可选提示，不参与 SQL 过滤
- **管理员端 `UserModelOptionsInterface`** 已受 `ManagerAuthMiddleware` 保护
- **空 user/model**：管理员端不指定 → 走全站聚合（无安全风险，与现状一致）
- **大表扫描**：指定 user+model 后只扫一张分表，性能优于全表扫描
