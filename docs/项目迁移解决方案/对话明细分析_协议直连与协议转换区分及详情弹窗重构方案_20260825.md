> 阶段：阶段 AM（持续累积，单一事务记录重构）

> 关联文档：[管理员与用户Web服务双构建隔离升级方案_20260825.md](./管理员与用户Web服务双构建隔离升级方案_20260825.md)、[AI代理模块排查报告_20260824.md](./AI代理模块排查报告_20260824.md)

## 1. 背景与目标

### 1.1 用户反馈

当前 `/ChatAnalysis`（对话明细分析）页面无法清晰区分两类代理行为：

- **协议直连-转发代理**（Anthropic↔Anthropic 或 OpenAI↔OpenAI）：数据包字段 `DstEndPointAlgorithmType=1`，转发体与原始协议体等价。
- **协议转换-转发代理**（Anthropic↔OpenAI 或 OpenAI↔Anthropic）：数据包字段 `DstEndPointAlgorithmType=2`，经协议转换层改写。

列表页仅有「协议」一列（基于 `ProtocolType`），缺少「转发类型」字段，无法直观区分直连/转换；详情弹窗虽然提供 JSON 美化 / SSE 解析 / 聚合解析四种视图，但全部塞在同一个 `<pre class="log-box">` 中，存在以下问题：

1. 复制按钮复制的是原始 `detailValue`，不是当前视图的内容（ChatAnalysis.jsx:388 的已知 bug）。
2. JSON 视图无法折叠，6 字段最高 80KB 一次性渲染。
3. SSE 解析仅显示一整块文本，无法按 event 拆分；聚合视图也只是纯文本。
4. 缺少元信息头部（时间/耗时/Tokens/大小）与底部状态栏，整体布局简陋。

### 1.2 目标

- **列表区分**：列表新增「转发类型」列徽标（直连=🔗/转换=🔄）+「转发类型」下拉筛选。
- **详情重构**：三段式布局（头部 + Tab + 底部），body 类字段四视图切换（原文 / JSON 美化 / SSE 解析 / 聚合解析），SSE 按 event 拆卡片，聚合分块展示（usage / tool_calls / event_types / 文本）。
- **复制按钮**：修复为「复制当前视图内容」。
- **共用工具抽取**：`parseSSEEvents` / `aggregateSSE` / `prettyJSON` / `renderJsonTree` 抽出到 `ClientWeb/src/shared/`，便于其它页面复用。
- **双构建隔离**：保持 `__APP_ROLE__` 字面量门控与 `isAdminRole()` UI 分支，构建后 grep 验证 `dist-user` 不含管理代码。

## 3. 协议判断逻辑

### 3.1 一级标签

| `DstEndPointAlgorithmType` | 标签 | 含义 |
|---|---|---|
| 1 | 🔗 协议直连（Direct） | 转发协议 = 客户端协议（Anthropic↔Anthropic 或 OpenAI↔OpenAI） |
| 2 | 🔄 协议转换（ProtocolConverter） | 转发协议 ≠ 客户端协议（Anthropic↔OpenAI 互转） |
| 0 或其他 | 未知 | 旧数据或异常 |

### 3.2 辅助判断（仅作详情头部副标题）

```
direct 强校验 = (RequestBody == RequestSrcProtocolBody) AND (ResponseBody == ResponseSrcProtocolBody)
```

- 同协议直连：`direct 强校验 = true`
- 协议转换：`direct 强校验 = false`（任一 body 已被协议转换层改写）

### 3.3 显示策略

- 列表徽标与详情头部均以 `DstEndPointAlgorithmType` 字段为权威展示。
- 「强校验结果」仅在详情头部作为副标题出现（如：「强校验：转换（响应体被改写）」），便于诊断配置异常（标签说直连但实际响应被改写的极端情况）。

## 4. 列表页改造方案

### 4.1 新增「转发类型」列

在 `dst_model_name` 列之后新增列：

```jsx
{ key: 'dst_endpoint_algorithm_type', title: '转发类型', width: 110,
  render: (v) => (
    <span className={`protocol-badge ${protocolBadgeClass(v)}`} title={protocolBadgeTitle(v)}>
      {protocolBadgeText(v)}
    </span>
  ),
},
```

`protocolBadge*` 工具函数（ChatAnalysis.jsx 内本地，10 行）：

- `v === 1` → `🔗 直连` + `.direct` 类
- `v === 2` → `🔄 转换` + `.converter` 类
- 其它 → `未知` + `.unknown` 类

### 4.2 新增「转发类型」筛选

在「协议」下拉之后新增下拉：

```jsx
<select value={filterAlgorithmType} onChange={e => setFilterAlgorithmType(Number(e.target.value))}>
  <option value={0}>全部转发类型</option>
  <option value={1}>🔗 协议直连</option>
  <option value={2}>🔄 协议转换</option>
</select>
```

`doQuery` 提交时附带 `filter_algorithm_type: filterAlgorithmType`。

### 4.3 后端联动（小幅扩参）

需要 3 个对称改动：

1. `ServerGo/models/subtable.go` 的 `QueryAgentHttpTransactions` 函数签名追加 `filterAlgorithmType int`，并在循环内追加 `Where("dst_endpoint_algorithm_type = ?", filterAlgorithmType)` 分支（>0 时启用）。
2. `ServerGo/api/server_api_manager_chat_analysis.go` 的 `ChatAnalysisInterfaceRequest` 结构体加 `FilterAlgorithmType int \`json:"filter_algorithm_type"\`` 字段并透传。
3. `ServerGo/api/server_api_user_chat_analysis.go` 的 `ChatAnalysisInterfaceRequest` 同上对称改动。

筛选逻辑与现有 `FilterProtocolType` / `FilterStatus` 等对称实现，无破坏性。

## 5. 详情 Modal 重构方案

### 5.1 三段式布局

```
┌─────────────────────────────────────────────┐
│ header.detail-head                          │
│  时间 / 请求方法 / 状态 / 耗时 / Tokens     │
│  源协议={ProtocolType} | 转发类型={徽标}    │
│  强校验：转换（响应体被改写）               │
├─────────────────────────────────────────────┤
│ nav.detail-tabs                             │
│  [请求体(转发)] [响应体(转发)]              │
│  [请求体(原始协议)] [响应体(原始协议)]      │
│  [请求头] [响应头]                          │
│  ─── 仅 body 类字段显示下方 ───             │
│ nav.detail-views                            │
│  [原文] [JSON美化] [SSE解析] [聚合解析]     │
├─────────────────────────────────────────────┤
│ main.detail-body                             │
│  (动态渲染：raw / JsonTree / SseEventList   │
│  / AggregateView)                           │
├─────────────────────────────────────────────┤
│ footer.detail-foot                          │
│  字节数 · 行数 | [复制当前视图] [全屏]      │
└─────────────────────────────────────────────┘
```

### 5.2 Tab 列表（沿用 `DETAIL_FIELDS`）

| key | 标签 | 是否 body |
|---|---|---|
| `request_body` | 请求体(转发) | ✅ |
| `response_body` | 响应体(转发) | ✅ |
| `request_src_protocol_body` | 请求体(原始协议) | ✅ |
| `response_src_protocol_body` | 响应体(原始协议) | ✅ |
| `request_headers` | 请求头 | ❌（仅原文） |
| `response_headers` | 响应头 | ❌（仅原文） |

### 5.3 body 类字段视图切换

四个互斥视图（`detailView` state：`raw` / `json` / `sse` / `agg`）：

| 视图 | 渲染组件 | 数据来源 |
|---|---|---|
| raw | `<pre class="log-box">` | `detailValue`（原始字符串） |
| json | `<JsonTree>` | `JSON.parse(detailValue)` |
| sse | `<SseEventList>` | `parseSSEEvents(detailValue)` |
| agg | `<AggregateView>` | `aggregateSSE(detailValue)` |

### 5.4 复制按钮修复

新增 `getShownContent()` 函数：

```js
function getShownContent() {
  const v = detailValue || '';
  switch (detailView) {
    case 'raw': return v;
    case 'json': return prettyJSON(v);
    case 'sse': return parseSSEEvents(v).map(e => `${e.event ? `event: ${e.event}\n` : ''}data: ${e.raw}`).join('\n\n');
    case 'agg': return aggregateToText(aggregateSSE(v));
    default: return v;
  }
}
```

按钮 `onClick={() => navigator.clipboard.writeText(getShownContent())}`。

## 6. 共用工具抽取

### 6.1 `ClientWeb/src/shared/sse.js`（新建）

从 `ChatAnalysis.jsx:29-79` 原样抽离 `parseSSEEvents` 与 `aggregateSSE`，加 JSDoc + 边界注释。零行为变更。

```js
// 导出
export function parseSSEEvents(text) → [{event, raw, parsed}]
export function aggregateSSE(text) → {textParts, usage, toolCalls, eventTypes}
```

边界处理：
- 空字符串 → `[]` / `{textParts:[], usage:{}, toolCalls:[], eventTypes:{}}`
- 非 SSE（无 `data:`）→ `[]`
- `data:` 非 JSON → `parsed = null`，`raw` 保留原文

### 6.2 `ClientWeb/src/shared/json.js`（新建）

```js
// 导出
export function prettyJSON(s) → string  // 失败时返回原字符串
export function renderJsonTree(value, opts) → ReactNode[]  // 递归渲染可折叠树
```

`renderJsonTree` 关键设计：
- object/array：`<details><summary>{key}: {type}</summary>...</details>`
- 字符串：引号包裹 + `.string` 类（绿）
- 数字：`.number` 类（橙）
- 布尔：`.boolean` 类（紫）
- null：`.null` 类（灰）
- 数组项：`<details><summary>[{idx}]: {type}</summary>...</details>`

> 注：`renderJsonTree` 由 `JsonTree.jsx` 组件调用，组件本身放在 `components/` 而非 `shared/`（组件属于表现层）。
