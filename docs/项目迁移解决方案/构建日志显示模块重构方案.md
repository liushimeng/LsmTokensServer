# 构建日志显示模块重构方案

> 阶段 AK | 2026-08-25

## 1. 背景

在阶段AH（commit d385ff8）中，构建日志弹窗功能被删除（与源码/README弹窗一起）。原版实现极为简单：

- **后端**：读取 `LsmTokensServerBuildDateTime.log` 纯时间戳文件，返回 `{lines: string[], count: number}`
- **前端**：`<div className="log-box">` 纯文本展示，无分页、无结构化信息

现在需要以增强版重新实现该功能，使其能展示丰富的构建信息，支持分页，界面美观。

## 2. 需求分析

### 2.1 信息维度

每条构建记录应包含：

| 字段 | 来源 | 说明 |
|------|------|------|
| `time` | `date '+%Y-%m-%d %H:%M:%S'` | 构建时间 |
| `git_hash` | `git log -1 --pretty=%h` | Git 短哈希（7位） |
| `git_msg` | `git log -1 --pretty=%s` | Git 最新提交信息 |
| `mode` | 脚本参数解析 | 构建模式：`restart` / `build-only` / `skip-web` |
| `web_ok` | 前端构建结果 | `true`=成功 / `false`=失败 / `null`=跳过 |
| `backend_ok` | 后端构建结果 | `true`=成功 / `false`=失败 |

### 2.2 前端展示

- 卡片式布局，每条记录一张卡片
- 时间突出显示
- Git 提交信息：短哈希（等宽字体）+ 提交描述
- 构建模式标签（彩色徽章）
- 前端/后端状态指示器（✓ 绿色成功 / ✗ 红色失败 / - 灰色跳过）
- 服务端分页，默认每页 20 条，可选 10/20/50/100

### 2.3 兼容性

- 旧格式（纯时间戳行）自动兼容：解析失败的行以降级模式展示（仅显示时间）
- 日志文件最大 500 条，超出截断尾部

## 3. 技术方案

### 3.1 构建脚本改造 — `rebuild_restart_app.sh`

**修改位置**：L218-L226（记录编译时间到日志文件）

**新逻辑**：
1. 在后端构建完成后、记录日志前，获取 git 信息：
   ```bash
   GIT_HASH=$(git log -1 --pretty=%h 2>/dev/null || echo "unknown")
   GIT_MSG=$(git log -1 --pretty=%s 2>/dev/null || echo "unknown")
   ```
2. 根据 `MODE` 和 `SKIP_WEB` 变量确定构建模式标签
3. 前端构建结果由 Step 1 执行是否成功决定（`SKIP_WEB=false` 时记录成功/跳过）
4. 后端构建结果由 Step 3 执行是否成功决定
5. 构造 JSON 对象写入日志文件（prepend 方式，保持最新在头部）
6. 日志文件行数上限 500，超出截断

**JSON-lines 格式**（每行一个 JSON 对象）：
```json
{"time":"2026-08-25 18:54:58","git_hash":"6fc62bc","git_msg":"阶段AJ：修复模型被禁用仍然被路由到的bug","mode":"restart","web_ok":true,"backend_ok":true}
```

### 3.2 后端 API — `buildLogInterfaceHandle`

**文件**：`ServerGo/api/server_api_common_info.go`

**接口**：`GET /BuildLogInterface?page_num=1&page_size=20`

**请求参数**：

| 参数 | 类型 | 默认 | 范围 | 说明 |
|------|------|------|------|------|
| `page_num` | int | 1 | ≥1 | 页码 |
| `page_size` | int | 20 | 10-100 | 每页条数 |

**响应结构**：
```json
{
  "records": [
    {
      "time": "2026-08-25 18:54:58",
      "git_hash": "6fc62bc",
      "git_msg": "阶段AJ：修复模型被禁用仍然被路由到的bug",
      "mode": "restart",
      "web_ok": true,
      "backend_ok": true
    }
  ],
  "totalCount": 103,
  "totalPages": 6,
  "currentPage": 1
}
```

**实现要点**：
- 使用 `system.GetProjectDir()` 定位日志文件
- 逐行 `json.Unmarshal` 解析，无效行以降级结构体填充（仅 time 字段）
- 内存分页（文件通常 <500 行，全量读取后 slice）
- 设置 `setNoCacheHeaders(w)` 避免浏览器缓存

### 3.3 路由注册 — `routes.go`

在 `RegisterManagerAPIRoutes` 和 `RegisterUserAPIRoutes` 中分别注册：
```go
mux.HandleFunc("/BuildLogInterface", buildLogInterfaceHandle)
```

### 3.4 前端组件 — `BuildLogDialog`

**文件**：`ClientWeb/src/components/ToolbarDialogs.jsx`

**组件设计**：
- 接收 `{ onClose }` props
- 首次加载调用 `get('BuildLogInterface?page_num=1&page_size=20')`
- 分页切换时重新请求对应页
- 加载中/错误/空状态处理

**UI 布局**（单条记录卡片）：
```
┌─────────────────────────────────────────────────┐
│  2026-08-25 18:54:58          [restart] [✓Web] [✓Go] │
│  6fc62bc  阶段AJ：修复模型被禁用仍然被路由到的bug    │
└─────────────────────────────────────────────────┘
```

- 左侧彩色边框条：全部成功=绿色、部分失败=红色、跳过=灰色
- 时间：14px 加粗
- 模式标签：圆角小徽章
- Git 信息：hash 用等宽字体，message 超长截断

### 3.5 CSS 样式

**文件**：`ClientWeb/src/index.css`

新增样式类（遵循现有命名规范）：
- `.buildlog-list` — 列表容器，flex 列，gap 8px
- `.buildlog-card` — 卡片，带左边框色条，圆角，hover 阴影
- `.buildlog-head` — 卡片头部（时间 + 标签行）
- `.buildlog-time` — 时间文字，14px 加粗
- `.buildlog-badges` — 右侧标签组
- `.buildlog-badge` — 单个标签（圆角，小字号）
- `.buildlog-badge.mode-restart` — 蓝色
- `.buildlog-badge.mode-build-only` — 灰色
- `.buildlog-badge.mode-skip-web` — 橙色
- `.buildlog-badge.ok` — 绿色
- `.buildlog-badge.fail` — 红色
- `.buildlog-badge.skip` — 灰色
- `.buildlog-git` — Git 信息行
- `.buildlog-hash` — 等宽字体 hash
- `.buildlog-msg` — 提交信息，溢出省略
- 响应式：≤600px 卡片内元素换行堆叠
