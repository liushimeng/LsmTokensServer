# 阶段U：前端国际化（i18n）多语言方案

> 日期：2026-08-26  
> 阶段：U（国际化 / Internationalization）  
> 影响范围：`ClientWeb/src/` 全部页面与组件

---

## 1. 需求概述

为 **管理员 Web 服务**（`dist-manager`）和 **用户 Web 服务**（`dist-user`）的菜单栏添加语言切换下拉菜单，支持：

| 语言 | 标识 | 旗帜 |
|------|------|------|
| 简体中文 | `zh-CN` | 🇨🇳 |
| English | `en` | 🇬🇧 |
| 日本語 | `ja` | 🇯🇵 |

所有 Web 页面和控件文案需支持动态切换，无需刷新页面。

---

## 2. 现状分析

### 2.1 无 i18n 体系

- 全部 UI 文案以简体中文硬编码在 JSX 中
- 无 i18n 库依赖（`package.json` 仅含 `react`、`react-dom`、`vite`）
- 日期/数字格式化使用 `toLocaleString('zh-CN')` 固定中文区域

### 2.2 双构建隔离约束

- `__APP_ROLE__` 是 Vite `define` 编译期常量（`'manager'` / `'user'`）
- 语言切换是**运行时行为**，与角色构建正交——同一套翻译文件在两个构建中共享
- 翻译文件作为 JSON 静态资源打包，不增加额外网络请求

### 2.3 路由与组件结构

- 自定义 hash 路由（`App.jsx`），无 React Router
- 16 个页面组件 + 6 个共享组件 + 1 个导航配置
- 所有组件均为函数式组件，适合 Context 注入

---

## 3. 架构设计

### 3.1 技术选型

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| **react-i18next / i18next** | 生态丰富、插值/复数/命名空间 | 增加 ~15KB 依赖，项目当前零依赖 | ❌ 过重 |
| **自定义 Context + JSON** | 零依赖、完全可控、与现有架构一致 | 需自行实现插值 | ✅ 采用 |

选择 **自定义 React Context + JSON 翻译文件** 方案：
- 零额外依赖，保持项目轻量
- 与现有 `__APP_ROLE__` 编译期常量模式一致
- 完全可控，无黑盒

### 3.2 目录结构

```
src/i18n/
├── index.js                 # 统一导出入口
├── I18nContext.jsx          # React Context + Provider
├── useI18n.js               # 便捷 Hook：const { t, locale, setLocale } = useI18n()
├── interpolate.js           # 字符串插值工具：t('key', { name: 'Alice' })
├── format.js                # 区域感知的日期/数字格式化
├── LanguageSwitcher.jsx     # 语言切换下拉菜单组件
└── locales/
    ├── zh-CN.json           # 简体中文（源语言）
    ├── en.json              # English
    └── ja.json              # 日本語
```

### 3.3 数据流

```
┌─────────────────────────────────────────────────────┐
│  I18nProvider (App.jsx 顶层)                        │
│  ┌───────────────────────────────────────────────┐  │
│  │  state: locale (from localStorage / navigator)│  │
│  │  translations: { ... } (按 locale 加载)       │  │
│  │  t(key, vars) → 翻译字符串                    │  │
│  │  setLocale(locale) → 切换语言                 │  │
│  └───────────────────────────────────────────────┘  │
│         │                                            │
│         ▼                                            │
│  ┌─────────────┐  ┌──────────────┐  ┌────────────┐  │
│  │ Layout      │  │ SideNav      │  │ Pages...   │  │
│  │ (header)    │  │ (nav items)  │  │ (16 pages) │  │
│  └─────────────┘  └──────────────┘  └────────────┘  │
│         │                                            │
│         ▼                                            │
│  LanguageSwitcher (header 工具栏)                    │
└─────────────────────────────────────────────────────┘
```

### 3.4 翻译键命名规范

采用 **二级命名空间** 结构：

```
{namespace}.{key}
```

| 命名空间 | 覆盖范围 |
|----------|----------|
| `common` | 通用按钮、状态、提示（所有页面共享） |
| `nav` | 侧边栏导航菜单项 |
| `login` | 用户登录页 |
| `managerLogin` | 管理员登录页 |
| `home` | 首页仪表盘 |
| `userManage` | 用户管理页 |
| `chatAnalysis` | 对话分析相关页面 |
| `aiRouteManage` | 智能路由管理 |
| `modelInfo` | 模型统计 |
| `agentInfo` | Agent 统计 |
| `protocolConvert` | 协议转换分析 |
| `spider` | 爬虫数据源 / 每日信息 |
| `cleanup` | 数据清理报告 |
| `dstEndPoint` | 目标端点管理 |
| `toolbar` | 工具栏弹窗 |
| `datatable` | 数据表格通用 |
| `errors` | 错误提示 |

### 3.5 插值语法

```
{variableName}  →  简单插值
```

示例：
```json
{ "total": "共 {count} 条" }
```
```javascript
t('datatable.total', { count: 42 })  // → "共 42 条"
```

### 3.6 语言切换持久化

- 存储键：`lsm_locale`
- 存储位置：`localStorage`
- 默认值：`navigator.language` 匹配 → `zh-CN` / `en` / `ja`，否则 `zh-CN`
- 切换时：更新 state → 写入 localStorage → 组件树重新渲染

### 3.7 区域感知格式化

扩展 `shared/format.js`，根据当前 i18n locale 选择 `Intl` 区域：

| i18n locale | Intl locale |
|-------------|-------------|
| `zh-CN` | `zh-CN` |
| `en` | `en-US` |
| `ja` | `ja-JP` |

## 4. 语言切换器设计

### 4.1 位置

在 `Layout.jsx` 的 header 工具栏区域，角色徽章左侧，添加语言切换下拉菜单。

### 4.2 交互

```
┌──────────────────┐
│ 🇨🇳 中文  ▼      │  ← 点击展开
├──────────────────┤
│ 🇨🇳 中文         │  ← 当前选中（高亮）
│ 🇬🇧 English      │
│ 🇯🇵 日本語       │
└──────────────────┘
```

### 4.3 样式

- 与现有工具栏按钮风格一致（CSS 变量驱动）
- 下拉菜单使用纯 CSS（无需额外组件库）
- 移动端自适应

---

## 5. 迁移策略

### 5.1 分步迁移

1. **Phase 1**：搭建 i18n 基础设施（Context、Provider、Hook、翻译文件）
2. **Phase 2**：更新布局与导航组件（Layout、SideNav、ToolbarDialogs、navConfig）
3. **Phase 3**：更新所有 16 个页面组件
4. **Phase 4**：更新共享组件（Modal、DataTable、AggregateView 等）
5. **Phase 5**：更新 format.js 支持区域感知
6. **Phase 6**：编译验证 + 双构建产物 grep 复验

### 5.2 迁移原则

- 每个页面独立迁移，确保迁移过程中系统始终可运行
- 翻译键按命名空间组织，避免全局污染
- 硬编码中文 → `t('namespace.key')` 一一对应
- 插值变量使用 `{varName}` 语法
- 保留源语言（中文）作为 fallback
