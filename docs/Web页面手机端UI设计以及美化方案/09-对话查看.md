# 09 - 对话查看（ChatDialog）

> 全局规范见 [00 文档](00-总体设计方案与移动端规范.md)；本页是全部页面中结构最简单者，几乎完全由全局规则覆盖。

## 1. 页面定位与功能需求

两步查询页：输入用户名拉模型列表（action=models）→ 选模型拉对话配置（action=config），展示代理地址、API Key（可显隐）、协议类型与目标源站列表，供用户复制拼接 API 地址。核心诉求：手机上能顺畅完成两步选择，并能**准确复制**完整 API 地址与 API Key。

## 2. 现状结构（简要）

文件：`src/pages/ChatDialog.jsx`。
- 工具栏 4 控件：用户名输入、"加载模型列表"按钮、模型下拉（选项含掩码 Key）、"查看对话配置"按钮。
- 卡片「模型列表」：4 列表（ID/模型名称/API Key/操作-查看配置），仅在未加载配置时显示。
- 卡片「对话配置（模型名）」：kv 8 项——用户名、模型 ID、协议类型、API Key（显隐按钮）、代理地址、代理路径、完整 API 地址。
- 卡片「目标源站列表」：5 列表（ID/平台/源站模型/协议/状态圆点），无操作列。
- 无弹窗、无图表、无删除操作。

## 3. 手机端布局方案

### ≤860px
- 工具栏 4 控件换行（00§3.6）；两张表横向滚动（00§3.5 策略 1）。

### ≤600px
- 工具栏全宽堆叠（00§3.6）：

```
┌────────────────┐
│ 用户名           │
│ [加载模型列表]    │
│ 模型 ▼          │
│ [查看对话配置]    │
├────────────────┤
│ 对话配置（xxx）   │
│ 用户名: …        │
│ API Key: •••• 显示│
│ 完整 API 地址:    │
│ https://…（整行可换行）│
├────────────────┤
│ 目标源站（卡片模式）│
└────────────────┘
```

- 两张 4~5 列小表启用卡片模式（00§3.5 策略 2），"查看配置"按钮整行。
- kv 区单列堆叠；「完整 API 地址」「API Key」两个长值行 `word-break: break-all`（页面级微调）。
- 本页弹窗：无，00§3.4 不涉及。

## 4. 交互设计

- **复制友好性**是手机端重点：完整 API 地址与明文 API Key 需可被长按选中——确认全局未设 `user-select:none` 覆盖；建议（页面级微调）在两行右侧加"复制"小按钮（`navigator.clipboard.writeText` + 成功反馈），≥40px 命中区（00§5）。若本期不加按钮，至少保证 break-all 后整行可选。
- API Key 显隐切换按钮与 Key 同行，手机上整行排列（field-inline 已有），按钮加高。
- 模型下拉选项文本为"模型名（掩码Key）"，手机上原生 select 弹层由系统渲染，无需适配。
- 两步加载的 loading 文字（"对话配置加载中…"）整行显示，保留。
- 路由带 user_name 自动拉列表、带 model_name 自动拉配置：保留，移动端进入即达目标配置。

## 5. 美观美化方案

- 沿用 00§4；kv 的 dd 中 code 值用浅底色块（`var(--primary)` 5% 透明度底 + 6px 圆角），区分"可复制数据"与普通文本。
- 「目标源站列表」状态圆点 + 启用/停用在卡片模式下首行展示。
- 本页信息密度低，手机端无需额外压缩；卡片间距按 00§3.3。
