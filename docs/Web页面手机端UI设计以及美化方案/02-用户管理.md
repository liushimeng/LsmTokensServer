# 02 - 用户管理（UserManage，管理端）

> 全局规范见 [00 文档](00-总体设计方案与移动端规范.md)，本文引用其章节号。

## 1. 页面定位与功能需求

管理员管理用户及其名下模型：用户 CRUD、启停用、协议开关（Anthropic/OpenAI）；行内展开模型列表（模型 CRUD + 启停）；从模型行跳转五个分析页。核心诉求：手机上能完成「找用户 → 展开模型 → 点分析页跳转」主链路。

## 2. 现状结构（简要）

文件：`src/pages/UserManage.jsx`。
- 工具栏：刷新、+ 添加用户。
- 主表 7 列：ID、用户名、手机号、用户状态、Anthropic、OpenAI、操作列 4 按钮（禁用/启用、编辑、删除、查看模型 ▲▼）。
- 行内展开区：子工具栏（模型列表标题 + 添加模型）+ 子表 6 列（ID、模型名称、API Key 脱敏、状态、分析列 5 链接、操作列 3 按钮）。
- 弹窗 1「添加/编辑用户」宽 480：用户名/密码/手机号/两个协议复选框。
- 弹窗 2「添加/编辑模型」宽 420：所属用户（禁用态）、模型名称。

## 3. 手机端布局方案

### ≤860px
- 主表横向滚动 + 密度收紧（00§3.5 策略 1）；弹窗仍居中但受 `max-width: 100vw` 约束（Modal 内联 width 被 00§3.4 规则覆盖仅限 ≤600px，861~600 之间由 `width:100%` + mask padding 24px 保证不溢出）。

### ≤600px
- 主表卡片模式（00§3.5）：用户名作首行，两个协议状态相邻行，操作列 4 按钮在卡片底部自动横排（卡片模式下 `white-space: normal` + 按钮自动换行）。
- **行内展开模型区**：展开区渲染在卡片流之后，子表同样卡片模式；「分析」列 5 个链接在卡片格内自动换行成两行，链接命中区加大（链接 padding 4px 6px，页面级 CSS）。
- 弹窗全屏（00§3.4），表单竖排天然适配。

```
┌──────────────┐
│ [刷新] [+添加用户]│
│ ┌用户卡片───┐ │

```

## 4. 交互设计

- 「查看模型」展开/收起在卡片模式下操作列末位整行按钮，▲▼ 状态保留。
- 删除/禁用 confirm 原生弹窗保留；跳转链接带 `?user_name=..&model_name=..` 不变（00§6 不砍功能）。
- 操作列按钮在卡片模式下换行排列，不再用 `{' '}` 空格挤压——由卡片模式 td 的 flex 布局自然分隔。

## 5. 美观美化方案

- 沿用 00§4。协议状态（启用/禁用）文字加 `status-dot` 圆点风格统一。
- 展开区与主卡片之间保留 12px 间距，子卡片左侧加 3px 主色边条标识从属关系（页面级 CSS，可选）。
