# 07 - 对话浏览与汇总统计（ChatAnalysis / ChatAnalysisTotal）

> 全局规范见 [00-总体设计方案与移动端规范](00-总体设计方案与移动端规范.md)，本文仅描述两页差异，引用其章节号（如 00§3.5）。

## 1. 页面定位与功能需求

- **ChatAnalysis（对话明细分析）**：管理端多条件筛选 + 分页的对话明细查询页，支持单条大字段详情（请求/响应体、请求/响应头按需拉取）与批量删除（≤500 条/次）。核心诉求：手机上能完成「填 user/model → 筛选 → 翻页 → 看详情 → 勾选删除」全流程。
- **ChatAnalysisTotal（对话汇总统计）**：WebSocket 分 7 个 stage 流式推送的多维度统计页（KPI、Tokens、模型分布、时间分布、趋势、协议、Agent 工具），WS 不可用时回退 HTTP 全量。核心诉求：手机上纵向浏览各统计维度，流式进度可见、可取消。

## 2. 现状结构（简要）

### ChatAnalysis（`src/pages/ChatAnalysis.jsx`）
- 工具栏：13 个控件——用户名/模型名输入、时间跨度/每页/协议/目标模型/Agent工具/输入Tok/输出Tok 7 个下拉、方法/状态/URL/工具串 4 个输入、"取反"复选框、查询按钮、批量删除按钮。
- 表格 12 列：勾选、ID、时间、方法、URL（截 60 字）、状态（红绿）、目标模型、输入Tok、输出Tok、耗时、Agent工具、操作（详情）。
- 弹窗：`对话详情 #ID` 固定 width=860，内含 6 个字段 Tab 按钮 + kv 信息 + `pre.log-box`。
- 分页器：上一页/下一页。

### ChatAnalysisTotal（`src/pages/ChatAnalysisTotal.jsx`）
- 工具栏：用户名/模型名输入、时间跨度下拉（切换即重查）、查询统计/取消按钮、行内进度文字。
- 卡片组：4 张 KPI 卡；「Tokens 概览」（kv + 6 列日表）；「源站模型分布」9 列表；「时间分布」2 列表（█ 字符条形）；「用量趋势」5 列表；「协议分析」（12 项 kv + 3 张 2 列小表）；「Agent 工具」（kv + 5 列表）。
- 无弹窗；WebSocket 流式（chunk/done/error/busy）+ HTTP fallback。

## 3. 手机端布局方案

### ≤860px（平板/大手机）
- 两页工具栏控件自动换行（全局 00§3.6），不单独处理。
- ChatAnalysis 主表保留横向滚动 + 密度收紧（全局 00§3.5 策略 1）。
- ChatAnalysisTotal 卡片纵向堆叠，其内表格全部横向滚动。

```
[页面标题]
[用户名      ] [模型名    ]
[时间跨度▼] [每页▼] [协议▼]
[目标模型▼] [Agent工具▼]
[方法] [状态] [取反☑] ...
[查询] [批量删除(0)]
┌表格（横向滚动 ↔）┐
│ ID │ 时间 │ 方法 │…│
└─────────────────┘
```

### ≤600px（手机）
- 工具栏按 00§3.6 全宽堆叠：ChatAnalysis 的 13 个控件每行一个，URL/工具串输入占满整行；"查询"与"批量删除"按钮各整行排列，命中区 ≥40px（00§5）。
- ChatAnalysis 表格启用 DataTable 卡片模式（全局 00§3.5 策略 2）：每行一张卡，`data-label` 显示列名；勾选框置卡片首行，"详情"按钮整行。本表以浏览单条为主，**不建议** `cardMode={false}`。
- ChatAnalysisTotal：KPI 卡 2×2 网格（页面级微调，见 §6）；各统计表保留卡片模式；「时间分布」的 █ 字符条形在卡片模式下自然纵向排列，无需改动；12 项协议 kv 改为单列 dt/dd 堆叠。
- ChatAnalysis 详情弹窗按 00§3.4 全屏：6 个字段 Tab 按钮转为两行网格（grid 3 列），log-box 高度 `calc(100dvh - 头部 - Tab 区)`。

```
┌────────────────┐
│ 对话详情 #123   ✕ │
├────────────────┤
│[请求体][响应体][请求头]│
│[原始请求][原始响应][响应头]│
├────────────────┤
│ kv 信息（单列）   │
├────────────────┤
│ log-box 字段内容  │
│ （纵向滚动）      │
└────────────────┘
```

## 4. 交互设计

- **批量删除（ChatAnalysis）**：手机端勾选在卡片模式下为每卡首行复选框（≥40px 命中区，00§5）；批量删除按钮常驻工具栏底部整行，confirm 原生弹窗保留。
- **详情字段 Tab**：点击即按需拉取 + 内存缓存的逻辑不变；手机端 Tab 按钮 3 列网格避免横向滚动条。
- **WebSocket 流式（ChatAnalysisTotal）**：功能不砍（00§6）。进度文字（"扫描中… 已处理 N 行"）在手机端独占一行置于按钮下方；取消按钮 ≥40px；页面滚远后新 stage 卡片直接在下方追加，不做吸顶进度条（保持简单）。
- **路由带参自动查询**：两页均保留，手机端进入即触发，loading 状态文字整行显示。
- 状态码红绿着色在卡片模式下保留，确保弱网/户外可读性（配合 00§4 令牌色）。

## 5. 美观美化方案

- 沿用 00§4：卡片 10px 圆角 + 轻阴影、150~200ms 过渡、去 tap 高亮。
- ChatAnalysisTotal 的 4 张 KPI 卡在 ≤600px 用 2×2 网格（`grid-template-columns: 1fr 1fr`），数字字号 26px→20px，避免单列 4 卡过长。
- 「时间分布」█ 条形改用主色 `var(--primary)` 渲染（现状为默认文字色），卡片模式下每行一条更直观。
- ChatAnalysis 详情弹窗 kv 区在手机上压缩为 2 列自适应，log-box 等宽字体 12px。
- 批量删除按钮在选中数 >0 时才显示计数徽章，减少视觉噪音。
