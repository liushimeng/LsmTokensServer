> 工程：LsmTokensServer
> 阶段：20260903-01（智能路由算法兼容性增强）
> 范围：`ServerGo/models/agent_algorithm*.go`、`ServerGo/models/mysql_http_ai_route_manage.go`
> 关联需求：`docs/开发指南/AGENT_INDEX.md`、`docs/项目迁移解决方案/`

---

## 1. 背景与目标

### 1.1 问题背景

LsmTokensServer 智能路由当前支持三种已实现算法：

| 算法 ID | 名称 | 选源逻辑 | 状态保留 |
|---|---|---|---|
| 1 | **指定型** | `DstEndPointIDs[0]` | 仅内存中无运行时状态 |
| 2 | **稳定型** | `DstEndPointIDs[0]`，连续 3 次失败把第 0 个滚动到末尾 | 内存中仅保留 `stableFailureCounters[routeID]` 计数器（重启清零） |
| 3 | **经济型** | Session 粘性 + livePool 消费 | 内存中保留 `economicRouteState{routeID}.sessionIndex/sessionQueue/livePool/endpointFailureCount/cooldownEndpoints/knownEndpoints`（重启清零） |

Web 管理端允许在同一路由上动态切换算法策略类型（`AlgorithmStrategyType`）。当前 `UpdateAIRoute` 的处理逻辑（`mysql_http_ai_route_manage.go:480-511`）：

```go
if oldStrategy == AlgorithmStrategyType_Economic && updated.AlgorithmStrategyType != AlgorithmStrategyType_Economic {
    ResetEconomicRouteState(updated.ID)        // 切走时清空经济型状态
}
if updated.AlgorithmStrategyType == AlgorithmStrategyType_Economic {
    newEndpointIDs, _ := ParseDstEndPointIDList(updated.DstEndPointIDList)
    SyncEconomicRouteEndpoints(updated.ID, newEndpointIDs)
}
```

### 1.2 痛点

**指定型 / 稳定型 → 经济型 切换时**，当前 Session 正在使用的目标源站会被清空。新切到经济型后，对同一 Session 的下一次请求会：

1. `sessionIndex` 已被 `ResetEconomicRouteState` 清掉，命中不到旧映射；
2. 走「新 session 路径」，由 `hashSessionToEndpoint` 重新分配（结果取决于当前 livePool 状态，可能命中到任意可用源站）；
3. 导致用户当前正在进行的会话被「静默切换」到另一个源站。

**用户体验**：从稳定型切到经济型后，对话工具/聊天客户端收到的下一条消息被路由到与上一条不同的源站。可能引起：
- Anthropic / OpenAI 上下文不连续（无状态源站重启后丢失 history）；
- 协议转换（OpenClaw 等）路径中累积的对话上下文被切到另一实例；
- 用户感知到「AI 突然忘了上一轮讲过什么」，客诉风险。

### 1.3 目标

**保持当前 Session 正在使用的目标模型，不要切换**：

1. **指定型 → 经济型**：继承上一刻 Session 正在使用的源站，让新切到经济型后的第一次 SelectForSession 仍命中该源站。
2. **稳定型 → 经济型**：与上面同理，继承「当前生效源站」（即 `DstEndPointIDs[0]`，因为稳定型 `Select` 永远返回 `[0]`）。
3. **经济型 → 指定型 / 稳定型**：当前逻辑（`ResetEconomicRouteState`）保持不变。

## 2. 兼容方案设计

### 2.1 设计要点

**核心思路**：在 `UpdateAIRoute` 检测到算法类型「从非经济型切到经济型」时，把「当前生效源站」以「全 Session 通配键（wildcard）」的形式预填入经济型状态，让**所有**新 session 的首次 SelectForSession 都先命中这一预填映射。

为什么不直接把单个 Session 全部继承？

- 指定型 / 稳定型在内存里**没有按 Session 维度的运行状态**，没有「Session A 当前在源站 X、Session B 当前在源站 Y」这种粒度的信息；
- 即使按代理日志反查，也只能拿到「最近一次请求走了哪个源站」，无法保证这之前所有 Session 的源站都一致；
- 全 Session 通配的做法更保守：所有 Session 都先尝试走「当前生效源站」（指定型 / 稳定型的 `DstEndPointIDs[0]`），如果该源站当前**可用**（状态=1 且未冷却）则直接命中；若该源站被禁用 / 已冷却，再由 SelectForSession 走「新 session 路径」自动重新分配。

### 2.2 实现细节

#### 2.2.1 新增经济型状态字段

在 `economicRouteState` 中新增一个「全局预填 Session ID」常量 `EconomicWildcardSessionID`（值 `"__economic_wildcard__"`，不会与真实 Agent 工具发送的 session_id 冲突）：

```go
// EconomicWildcardSessionID 经济型「全 Session 通配」预填键
// 用于兼容指定型 / 稳定型 → 经济型 的算法切换场景：
// 切换前无 session 维度的运行时状态，把"当前生效源站"以通配键预填入
// sessionIndex/sessionQueue，所有新 session 的首次 SelectForSession 命中
// 该预填映射，避免当前正在使用的会话被静默切换到其他源站。
// 不与真实 session_id 冲突：约定真实 session_id 不允许包含"__"前缀。
const EconomicWildcardSessionID = "__economic_wildcard__"
```

#### 2.2.2 在 `UpdateAIRoute` 中新增兼容逻辑

将现有的两段 if 改造为三分支：

```go
// 经济型算法：在锁外同步状态（避免与 agentAIRouteMutex 交叉持锁）
//   - 切到非经济型：清空经济型状态（保持原行为）
//   - 非经济型 → 经济型：预填"全 Session 通配"映射到当前生效源站，避免当前会话被静默切换
//   - 保持/切回经济型：把 livePool + session 队列 + 失败计数与新源站列表对齐
if oldStrategy == AlgorithmStrategyType_Economic && updated.AlgorithmStrategyType != AlgorithmStrategyType_Economic {
    ResetEconomicRouteState(updated.ID)
}
if updated.AlgorithmStrategyType == AlgorithmStrategyType_Economic {
    newEndpointIDs, _ := ParseDstEndPointIDList(updated.DstEndPointIDList)
    SyncEconomicRouteEndpoints(updated.ID, newEndpointIDs)

    // v2.0.77 阶段BS：非经济型 → 经济型 的兼容处理：把当前生效源站预填为通配映射
    if oldStrategy != AlgorithmStrategyType_Economic && oldStrategy != 0 {
        // oldStrategy != 0 排除"首次创建路由即经济型"的场景（new route 无切换语义）
        if len(newEndpointIDs) > 0 {
            // 当前生效源站 = DstEndPointIDs[0]（与指定型/稳定型 Select 逻辑一致）
            currentEffective := newEndpointIDs[0]
            SeedEconomicWildcardSession(updated.ID, currentEffective)
        }
    }
}
```

#### 2.2.3 新增 `SeedEconomicWildcardSession`

```go
// SeedEconomicWildcardSession 把指定源站预填为经济型的"全 Session 通配"映射。
// 用途：非经济型（指定型/稳定型）→ 经济型 的算法切换兼容。
//   - 写入 sessionIndex[EconomicWildcardSessionID] 与 sessionQueue 队尾
//   - 把 currentEffective 从 livePool swap-remove（避免被 SelectForSession 的"新 session"路径再次分配）
//   - 若当前源站处于禁用 / 冷却状态，则写入映射但保留在 livePool，由 SelectForSession 兜底重选
//
// 注：不调用 ResetEconomicRouteState —— 仅追加一个通配键，不破坏其它状态。
func SeedEconomicWildcardSession(routeID uint64, currentEffective uint64) {
    state := getEconomicState(routeID)
    state.mu.Lock()
    defer state.mu.Unlock()

    // 校验当前源站仍可用；不可用时不消费 livePool（让 SelectForSession 兜底重选）
    enabled := true
    if cachedRoute, ok := GetCachedRouteByID(routeID); ok {
        enabled = isEndpointEnabled(cachedRoute, currentEffective)
    }
    inCooldown := isEndpointCoolingLocked(state, currentEffective)

    // 写入通配映射（不管是否可用，都写；SelectForSession 会基于可用性决定是否命中）
    entry := &sessionMapEntry{
        SessionID:  EconomicWildcardSessionID,
        EndPointID: currentEffective,
    }
    state.sessionIndex[EconomicWildcardSessionID] = entry
    // 清理已有队列项（避免重复）
    for i, e := range state.sessionQueue {
        if e.SessionID == EconomicWildcardSessionID {
            state.sessionQueue = append(state.sessionQueue[:i], state.sessionQueue[i+1:]...)
            break
        }
    }
    state.sessionQueue = append(state.sessionQueue, entry)

    // 仅在源站可用且未冷却时从 livePool swap-remove
    if enabled && !inCooldown {
        state.livePool = removeFromLivePool(state.livePool, currentEffective)
    }

    logger.Printf("[ECONOMIC] Route %d: seeded wildcard session → endpoint %d (enabled=%v, cooling=%v)",
        routeID, currentEffective, enabled, inCooldown)
}
```

#### 2.2.4 改造 `SelectForSession` 增加通配命中分支

在现有命中已有映射的逻辑之后、新 session 分配之前，插入通配命中分支：

```go
// 命中已有映射
if entry, ok := state.sessionIndex[sessionID]; ok { ... } // 既有逻辑保持不变

// v2.0.77 阶段BS：通配映射兜底命中（非经济型 → 经济型 切换兼容）
//   - 仅在真正的 session_id 未命中时生效
//   - 通配命中后删除通配条目，避免后续 session 都被错误吸到该源站
if _, hasReal := state.sessionIndex[sessionID]; !hasReal {
    if wEntry, wOK := state.sessionIndex[EconomicWildcardSessionID]; wOK {
        // 校验通配源站当前是否仍可用
        idx := -1
        for i, id := range route.DstEndPointIDs {
            if id == wEntry.EndPointID {
                idx = i
                break
            }
        }
        if idx != -1 {
            status := 1
            if idx < len(route.DstEndPointIDStatuses) {
                status = route.DstEndPointIDStatuses[idx]
            }
            epEnabled := true
            if ep, epOK := GetCachedDstEndPointByID(wEntry.EndPointID); epOK && ep.Status == 0 {
                epEnabled = false
            }
            if status == 1 && epEnabled {
                if deadline, cooling := state.cooldownEndpoints[wEntry.EndPointID]; !cooling || time.Now().After(deadline) {
                    // 命中通配：消费一次后清掉通配条目
                    delete(state.sessionIndex, EconomicWildcardSessionID)
                    for i, e := range state.sessionQueue {
                        if e.SessionID == EconomicWildcardSessionID {
                            state.sessionQueue = append(state.sessionQueue[:i], state.sessionQueue[i+1:]...)
                            break
                        }
                    }
                    // 为当前真实 session 写入独立映射（保证后续仍粘性）
                    realEntry := &sessionMapEntry{SessionID: sessionID, EndPointID: wEntry.EndPointID}
                    state.sessionIndex[sessionID] = realEntry
                    state.sessionQueue = append(state.sessionQueue, realEntry)
                    // LRU 驱逐
                    for len(state.sessionQueue) > EconomicSessionQueueMaxSize {
                        evicted := state.sessionQueue[0]
                        state.sessionQueue = state.sessionQueue[1:]
                        delete(state.sessionIndex, evicted.SessionID)
                    }
                    RecordSelection(AlgorithmStrategyType_Economic)
                    return wEntry.EndPointID, true
                }
            }
        }
    }
}

// 新 session 分配（既有逻辑保持不变）
```

**关键性质**：
- **只命中一次**：通配条目被消费后立即清掉，后续 session 走标准「哈希分配」逻辑（保证 Session 级负载均衡）。
- **复用同一个真实 session 的写入**：把真实 session_id 也写入 sessionIndex，让后续同一 session 的请求仍粘性命中同一源站（与原语义一致）。
- **自动重选**：通配源站被禁用 / 冷却时跳过通配分支，自动 fallthrough 到「哈希重选」。

#### 2.2.5 `SyncEconomicRouteEndpoints` 的边界处理

通配条目属于 sessionQueue / sessionIndex，按既有逻辑 `SyncEconomicRouteEndpoints` 会对映射到「被删 ID」的条目重新分配：

- 若管理员在切换算法后又删除通配源站：通配条目映射被重分配到剩余源站中随机一个；
- 若整个 DstEndPointIDs 被清空：通配条目直接被清理（`newEndpointIDs` 为空分支）。

**无需特别处理**：现有逻辑已正确覆盖。补一个测试断言。

### 2.3 不需要改动的部分

| 场景 | 当前行为 | 是否改 |
|---|---|---|
| **经济型 → 指定型** | `ResetEconomicRouteState(updated.ID)` | **不变**：经济型 session 映射本来就不属于指定型语义 |
| **经济型 → 稳定型** | `ResetEconomicRouteState(updated.ID)` | **不变**：理由同上 |
| **指定型 / 稳定型 → 指定型 / 稳定型** | 无变化 | **不变** |
| **经济型 → 经济型（同算法、仅改源站列表）** | `SyncEconomicRouteEndpoints` 对齐 livePool | **不变** |
| **首次创建路由** | 走 AddAIRoute，不触发 UpdateAIRoute 的算法切换逻辑 | **不变** |

### 2.4 数据流图

```
[Web UI: 切换算法]
        │
        ▼
┌────────────────────────┐
│ UpdateAIRoute(item)    │  数据库层（mysql_http_ai_route_manage.go）
│   oldStrategy = 经济型 ? │
│   updated.AlgorithmStrategyType = 经济型 ?
└────────┬───────────────┘
         │
         │  (1) 经济型 → 非经济型：ResetEconomicRouteState (不变)
         │  (2) 非经济型 → 经济型：
         │      ┌─ SyncEconomicRouteEndpoints ─┐
         │      │   把 livePool 与新源站列表对齐  │
         │      └────────────────────────────┘
         │      ┌─ SeedEconomicWildcardSession ─┐  ★ 本次新增
         │      │   把 DstEndPointIDs[0] 预填为通配 │
         │      └────────────────────────────┘
         │  (3) 经济型 → 经济型：SyncEconomicRouteEndpoints (不变)
         │
         ▼
   [下次 SelectForSession]
         │
         │ 真实 session_id 命中？→ 是 → 走原逻辑
         │                        │ 否 → ★ 检查通配映射
         │                              │ 命中 → 消费通配 + 写入真实映射 + 返回通配源站
         │                              │ 未命中 → 走「新 session 哈希分配」原逻辑
         ▼
       返回 endpoint ID
```

## 3. 兼容性分析

### 3.1 与现有测试的兼容性

| 已有测试 | 行为预期 | 影响 |
|---|---|---|
| `TestEconomicAlgorithmSwitchFromEconomic` | 经济型 → 非经济型：状态清空 | **不变**：现有 Reset 分支原样 |
| `TestEconomicConsumeSkipsRemovedEndpoint` | session→失效源站被清理并重选 | **不变**：通配映射不会与真实 session 冲突 |
| `TestEconomicSelectorSessionAffinity` | 同一 session 粘性 | **不变**：通配命中分支只在真实 session 未命中时触发 |
| `TestEconomicSyncEndpoints_Remove_ReassignSession` | 被删源站的 session 重分配 | **不变**：通配条目同样按 `removedSet` 重分配 |
| `TestEconomicSyncEndpoints_FiltersDisabled` | 同步时过滤禁用源站 | **不变**：通配仅在 SelectForSession 时校验可用性 |

### 3.2 边界场景

| 场景 | 行为 |
|---|---|
| 切换时路由无任何源站（`DstEndPointIDList=""`） | `SeedEconomicWildcardSession` 不被调用（`newEndpointIDs` 为空） |
| 切换时新源站列表不含通配源站（罕见：前端把 DstEndPointIDList 改了） | 通配条目由 `SyncEconomicRouteEndpoints` 重新分配到剩余源站 |
| 切换后第一次请求没有 session_id | 走原 Select 兜底逻辑（按 DstEndPointIDs[0]） |
| 切换后第一次请求有 session_id 但通配源站已禁用 | 通配命中分支校验失败，fallthrough 到「新 session 哈希重选」 |
| 切换后第一次请求有 session_id 且通配源站可用 | 命中通配，返回通配源站；后续同 session 仍粘性 |
| 切换后第二次请求（同 session） | sessionIndex 已有真实映射，走原粘性逻辑 |
| 切换后另一个 session 的请求（无通配可消费） | sessionIndex 无该 session、无通配，走「新 session 哈希分配」 |

### 3.3 风险评估

| 风险点 | 等级 | 缓解措施 |
|---|---|---|
| 通配键与真实 session_id 冲突 | 低 | `__economic_wildcard__` 含特殊前缀，且真实 session_id 由客户端控制，按惯例不会包含 |
| 切换后第一次请求延迟增加（多一次哈希 + 校验） | 低 | 仅一次命中分支，< 1μs |
| 通配源站被禁用时仍写入映射 | 低 | 通配命中分支校验可用性，自动 fallthrough |
| LRU 队列被通配条目占用 | 低 | 通配条目消费后立即清掉，且 LRU 上限 50 影响可忽略 |
| 并发：通配条目被多次命中 | 中 | 经济型状态用 `sync.Mutex` 保护，且通配命中后立即 delete |
