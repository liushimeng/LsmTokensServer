# 列表筛选状态记忆功能全站统一方案（F5/右键刷新不丢筛选）

> 日期：2026-09-27 ｜ 阶段号：CS ｜ 范围：ClientWeb 全部含 List/筛选/时间跨度的页面
> 问题单：管理端/用户端 `/AIRouteManage`「智能路由管理」时间列表选择「最近6小时」后，F5 刷新页面回落为默认档（就近 3 天档，实际显示 2 天档），筛选状态丢失。

## 1. 问题分析

### 1.1 根因

各列表页的时间跨度（`days`/span 编码：正值=天、负值=小时）与筛选字段（用户名/模型名/平台/协议类型等）均为 React `useState` 内存态：

- 档位通过 `useTimeSpanLevels()` 动态加载后，`useEffect` 用 `nearestSpan(levels, 默认值)` 初始化；
- **初始化时未读取 localStorage 中的历史选择**，变更时也未写回；
- F5 / 右键重新加载后组件树重建，状态全部回落默认档。

### 1.3 已有基础设施

- `shared/timeSpan.js`：`nearestSpan(levels, target)` 就近档迁移（旧值跨档位变更自动吸附）；
- `shared/useTimeSpanLevels.js`：动态档位 Hook（60s 模块缓存）；
- `shared/useStatsPageFilters.js`：ModelInfo/AgentInfo 的「userName+modelName+days」记忆范式（debounce 300ms 写盘、key 按角色隔离）；
- `components/DataTable.jsx`：排序状态 localStorage 持久化（`lsm:datatable:sort:{role}:{path}`）。

## 2. 解决方案设计

### 2.1 总体思路

新增**通用记忆工具模块** `ClientWeb/src/shared/listMemory.js`，把各页面重复的「读档→就近迁移→变更写盘」逻辑收敛为一处，各页面只声明 `pageKey`、默认值与字段清单：

1. `roleSuffix(isAdmin)`：角色隔离后缀（`manager`/`user`），与现有 key 命名风格一致；
2. `loadListMemory(key)` / `saveListMemory(key, obj)`：localStorage 读写（try/catch 容错，非法 JSON 返回 null）；
3. `usePersistedSpan(pageKey, isAdmin, defaultSpan, legacyKey?)`：
   - 内部复用 `useTimeSpanLevels()`；
   - 档位到达后初始化：`localStorage 记忆值 > legacyKey 兼容值 > defaultSpan`，统一经 `nearestSpan` 就近迁移（span 编码负值=小时，记忆「最近6小时」= `-6` 完整还原）；
   - `setDays` 变更即写盘（key：`lsm:{pageKey}:span:{role}`），无需 debounce（下拉单选）；
4. `useDebouncedMemorySave(key, payload)`：文本筛选字段 debounce 300ms 写盘（对齐 chat-analysis 既有行为）。

### 2.2 各页面改造清单

| 页面 | 记忆 key | 内容 |
|---|---|---|
| AIRouteManage | `lsm:airoute:span:{role}` | days（**主修复点**） |
| ChatAnalysisTotal | `lsm:chat_analysis_total:span:{role}` + `lsm:chat_analysis_total:filters:{role}` | days + userName/modelName |
| ChatAnalysisSession | `lsm:chat_analysis_session:span:{role}` + `:filters:` | days + userName/modelName |
| ChatAnalysisTask | `lsm:chat_analysis_task:span:{role}` + `:filters:` | days + userName/modelName |
| ProtocolConvertAnalyzer | `lsm:protocol_convert_analyzer:span:{role}` + `:filters:` | days + userName/modelName/protocolType |
| CleanupReport | `lsm:cleanup_report:span:{role}` | days（兼容迁移旧 key `lsm:cleanupReport:days:v1`，并补齐角色隔离） |
| SpiderDailyInfo | `lsm:spider_daily_info:filters:{role}` | platform/start_date/end_date/page_size（**URL query 优先**，query 缺失时回退记忆值） |

### 2.3 关键设计约束

- **路由 query 优先级最高**：`init.userName || saved.userName || ''`（保持从其他页跳转带参进入的行为不变）；
- **用户端 userName 不落盘/不还原**：管理端专属字段，用户端恒为空（`isAdmin && saved.userName`）；
- **不记忆的字段**：page 页码（AIRouteManage 已有分页记忆除外）、选中集合、弹窗表单、加载态——刷新后理应重置；
- **days===null 期间不发起查询**的既有守卫保持不变，避免记忆未就绪提前请求；
- **构建期常量 `__APP_ROLE__`**：SpiderDailyInfo/CleanupReport 无运行时 isAdmin，用 `__APP_ROLE__ === 'manager'` 生成角色后缀（双构建静态替换，用户端产物零管理代码）；
- **双构建隔离不受影响**：本方案仅改状态初始化与持久化，不新增接口与 import。

### 2.4 自检

- 新增 `ClientWeb/src/shared/listMemory.test.js`（node 直跑，localStorage mock）：读写容错、角色后缀、span 记忆值读取/回退逻辑；
- 回归既有自检：`node src/shared/timeSpan.test.js`、`node src/pages/chat-analysis/agentToolFields.test.js` 等；
- 前端构建：`cd ClientWeb && npm run build`（双产物 dist-manager/dist-user）；
- 集成验证：`./rebuild_restart_app.sh`（不带参数，完整重启）。

## 3. 验收标准

1. `/AIRouteManage` 选择「最近6小时」→ F5 刷新 → 时间列表保持「最近6小时」，统计按 6 小时口径加载；管理端/用户端记忆互不串扰；
2. 遍历 2.2 清单全部页面：修改筛选/时间档 → 刷新 → 状态完整还原；
3. 从其他页带 `?user_name=&model_name=` 跳转进入时，路由参数覆盖记忆值（行为不回退）；
4. `npm run build` 通过；用户端产物不含管理端专属代码（`__APP_ROLE__` 门控不变）；
5. 中文分阶段提交并推送双远端。
